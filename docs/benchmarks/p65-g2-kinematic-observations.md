## 接口与既有故障边界

`TyxWorldBatch.kinematics(keys=None)` 读取当前已提交状态，返回请求顺序的 `keys`、各行自由度数 `widths`、精确的 `int32 ticks` 和 `(W, 6)` 的只读、独立 FP32 `values`。自由球三维，前 3 列是世界位置，后 3 列是线速度。固定基座滑轨一维，第 0 列是 q，第 3 列是 q̇，其余为零。省略键时按登记顺序，显式键可重排或选子集。空选择不读设备，未知或重复键在读回前拒绝。

非空选择使用原有两个已提交缓冲的原生读回，HOST 按键和列构造连续批量结果。设备传输量取决于登记世界总数 W，每次读取 12W 个 FP32 和 W 个 int32，共 52W B。每次调用单列计入 `kinematics_downloaded_bytes`。物理 `step` 仍逐世界检查 4W B 接受标志后提交双缓冲。完整状态、受力、延时输入和局部恢复均使用现有 `snapshot/restore`。观测失败遵守原设备恢复路径，已经提交的状态和此前返回的帧保持可读。

## 原路径的实际成本

在原 G2 入口上，两个独立 CUDA 进程均先预热两个窗，再对五个 32 步窗分段。测量器包裹了真实 `step`、`snapshot` 及其内部方法，各窗先扣除嵌套时间再取阶段中位数。计时探针有自身开销。下表单位均为毫秒/32 步，单列中位数不具有可加性。

| 实测阶段 | W1 | W32 |
| --- | ---: | ---: |
| 整窗 | 11.829 | 17.485 |
| 物理核提交 / 同步 | 5.960 / 0.370 | 5.772 / 0.358 |
| 接受状态下载 / 验证 | 0.818 / 0.333 | 0.789 / 0.322 |
| 完整状态行 / 步号下载 | 0.721 / 0.536 | 0.741 / 0.578 |
| 逐行构造 WorldCheckpoint | 0.256 | 4.608 |
| 快照键、字典及其余开销 | 0.435 | 1.147 |
| 从公开检查点提取位置和速度 | 0.188 | 0.701 |
| 共同应用排序与六列验算 | 0.927 | 1.086 |

W32 的逐行检查点构造占五窗总壁钟的 26.2%，W1 为 2.1%。当前实现只改变 HOST 发布，并按实际读回记账。[分段探针](../../scripts/profile_kinematic_observations.py) · [观测实现](../../src/phymeo/backends/_world_kinematics.py)

## 同一物理输出的配对

六个独立进程分别运行 W1/W32 的三轮。每进程有两个独立工作区，同一批共址的 2 kg 自由球都从 z=2 m、v=0 开始，g_z=−8 m/s²，h=1/128 s。每个工作区先执行 1 个首步，再运行 5 个预热窗和 20 个计时窗，每窗 32 个物理步，窗间连续推进到步号 801。两个工作区逐窗交替谁先运行，第 1 和第 3 轮从完整接口开始，第 2 轮从新接口开始。

同一应用按外部世界键重排、存下每步六个 FP32 并验算闭式解，计时含物理提交、强制接受、状态读回、输出整理与共同校验。新旧两端每个窗都比较实际轨迹数组及 SHA。冷步和 20 个正式窗再分别与前批 Newton、Phymeo 独立进程的 SHA 比较。所有分量相等，最大位置、速度误差为 0。吞吐为 20 窗的总世界子步除以总壁钟。W32 每个工作区每轮有 640 次真实 CUDA 核提交与同步、20,480 个已接受世界步、0 次重新分配与 0 B 上传。接受标记下载 81,920 B，物理状态下载 1,064,960 B，合计 1,146,880 B。

此前 Newton 在另一个时段以同一应用读回合同实测 W32 为 124,620–145,939 世界子步/s。上表六个进程仅配对比较本次 Phymeo 的两个公开接口。首步共享当前进程加载状态，正式缓存与首步冷编译的数据见前批报告。[原跨引擎基准](p65-g2-newton-observed-free-fall.md) · [配对计时与状态审计](../../scripts/benchmark_kinematic_observations.py)

## 正确性与复现

4 个留出各通过 Phymeo interpret 与实际 CUDA。它们覆盖混合球/延时滑轨的维数、三维非对称状态、重排与部分选择、无效键和空选择、局部数值拒绝、局部 restore/reset 后延时驱动重放、观测读回故障后恢复，以及大于 2²⁴ 的步号精度。保存的上一帧不随继续推进改变。每次非空观测的设备计数也与声明的 52W B 相符。[专项测试](../../tests/scale/test_world_kinematics.py)

分别执行 `python scripts/profile_kinematic_observations.py --worlds 32 --cache-root <缓存> --out <新诊断JSON>` 和 `python -m pytest -q tests/scale/test_world_kinematics.py`。配对命令还需同轮次的两个历史 JSON，例如：

```powershell
python scripts/benchmark_kinematic_observations.py --worlds 32 --first full --cache-root $cache --out $fresh --previous-newton $newtonReceipt --previous-full $phymeoReceipt
```

原始状态、每窗时间、实际设备计数、守卫、离线审计脚本和结果位于 `artifacts/p65-night-g2-kinematic-observations-20261104-01/`。离线 `comparison.json` 的 SHA256 为 `466a347663b6548983ccae50b084e2f1bda3045a3402c514fff5ddf3e2349256`。第一轮 interpret 测试使用整数增益触发了既有模型的浮点类型检查，修正夹具后的 interpret 与 CUDA 收据分别为 `g2k-green-interpret-v2` 和 `g2k-green-cuda`。
