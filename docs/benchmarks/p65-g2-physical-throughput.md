# G2 常驻物理子步的同输出 CUDA 吞吐

在 RTX 4060 Laptop 上，32 个共址世界使用一个 `TyxWorldBatch`。对照为在同一设备上依次推进 32 个各自单独的 `TyxWorldBatch`。每个世界都从 2 m 的静止位置开始，以 1/128 s 的物理子步接受 −8 m/s² 重力。每种输出做三组独立进程配对，顺序依次为合批先、单跑先、合批先。W=1 和 W=32 注入不同的非连续世界键，原始物理状态和操作完全相同。[可执行基准](../../scripts/benchmark_resident_steps.py) · [此前轨迹、控制和复位验收](p65-g2-resident-world-step.md)

| ---: | --- | --- | --- | --- |

| 1 | 状态及完整检查点 | 0.98 / 1.05 / 1.00 | 3,503 / 3,872 / 3,598 | 9.05 / 8.19 / 8.76 |
| 32 | 逐步接受状态 | 31.40 / 33.12 / 33.70 | 142,295 / 150,263 / 153,525 | 6.82 / 6.61 / 6.23 |

上述速度比的分母是本项目同一 TYX 物理入口的独立工作区顺序调用。它仅适用于这个自由球工作负载。世界数为 32 时摊薄了每次 Python 提交、同步、标记回传和整理结果的开销。W=1 三种输出在三次配对中均没有超过原 10% 的暖态延迟回退线。静态碰撞查询另有不同读回和负载；密集几何也有大量 HOST 时间。[静态 G1](p65-world-partition.md) · [单世界复杂度 G4](p65-g4-world-geometry.md)

每次先单独测创建和首个物理步，再预热 5 个 32 步窗，测 20 个 32 步窗。W32 的每组每种方法接受 20,480 个世界子步。计时含所有请求的同步、接受标记与输出对象构造。校验及哈希在定时窗外。每个完整快照的世界键、时步、速度和位置逐一与半隐式闭式解比较，每项摘要的动能与球底高度同样核对。三种模式的 20 个逐窗全输出 SHA 和最终物理检查点均与其顺序基线相同。未用接受标记推测状态正确。

W32 合批的每个正式测量段中，标记、摘要和完整检查点分别读回 81,920、245,760、1,146,880 B，实际 kernel 数分别为 640、1,280、640。三种都没有新增设备分配、拓扑或控制上传。该批显式持有 7,220 B 设备缓冲；驱动与分配器总显存峰值未测。按窗的原始墙钟、p50/p95、冷首步和每次计数都保存在父 `artifacts/p65-20261104-0800/validation/resident-w{1,32}-pair-{1,2,3}/result.json`。用于波动判断的 W1 结果也完整保留。
