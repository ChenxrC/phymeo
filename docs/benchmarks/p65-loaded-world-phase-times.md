# 受载多世界物理步的墙钟分解

RTX 4060 Laptop 的四档 CUDA 窗口中，最大的 HOST 开销都在 `ClothLinkContacts._witness` 的单姿态胶囊–三角面最近特征查询。W32 每个四步窗调用 192 次，占带计时器总墙钟的 85.86%。相同窗口另有 64 次路径验证，每次覆盖入步至中点及中点至末态。这些路径均由界限检查判定，路径内部最近特征调用为零。[正式驱动](../../scripts/profile_loaded_worlds.py) · [最近特征和路径检查](../../src/phymeo/solvers/cloth_link_contact.py)

## 窗口和分母

每档单独起一个进程，固定 `h = 1/256 s`，一个窗含四个真实物理子步。W1 只取一个受载布面–滑轨世界。W4 包含受载布面–滑轨、自由球、分离布面–滑轨和延迟滑轨各一份。W16、W32 分别复制四、八份四世界单元，沿用不同的世界键、驱动和外载。每窗从同一检查点和历史开始。控制、物理推进、原有同步、接受标志、材料审计与全量检查点读回都计时。复位、设备计数与比较 SHA 在窗外。[冻结输入及公开输出](../../tests/scale/mixed_physical_cases.py)

同一合组实现每档测五对普通窗和带计时器窗，顺序交替，另有一次普通预热窗。吞吐分子为该组五个窗实际接受的世界子步数，分母为对应五窗墙钟总和。`配对时钟比` 是五个「带计时器窗墙钟 / 同对普通窗墙钟」的中位数。p95 取最近秩，第五个有序样本即该档最大值。W1 所有世界都受载，W4 以上每四个世界只有一个实际受载。两者不构成同内容的单世界扩展基准。

| 1 | 20 | 26.405 / 29.146 | 27.805 / 32.842 | 149.99 / 141.29 | 1.129 |
| 4 | 80 | 52.059 / 58.873 | 50.450 / 58.308 | 304.73 / 308.15 | 0.990 |

W1 的配对时钟比高出约 13%，W4/W16 略低于 1。这是单进程五对窗的测量，包含短窗抖动。历史 W32 的 1.327–1.477 倍使用同引擎逐世界调用作分母，本表使用相同合组实现的普通窗作分母。[历史 W32 合组与逐世界比较](p65-mixed-physical-w32.md)

W1 的独立引用是单世界材料求解器的首次调用。四步轨迹 SHA、24 次核、4 次同步、1,424 B 动态上传和 1,168 B 下载与合组暖窗一致。独立引用另上传 28 B 静态参数，分配 13 个设备缓冲并构建一次引擎，原生总上传量因此为 1,452 B。这次冷参考只用于核实状态与物理工作量。

## 调用边界

每个阶段使用实际 Python 方法入口和出口的墙钟，先扣除已计量的嵌套子调用。同一输入的五个带计时器窗合并后才计算阶段占比，每个窗的排他纳秒数之和须等于该窗总纳秒。静态见证含材料程序对入步、中点和末态三次 `WorldMaterial.geometry` 的见证查询。`path_check` 计路径的其余工作。连杆姿态计算与路径中嵌套的见证各自归类。材料地址、弹性、接受审计和发布也各自计量。未归因墙钟含窗口内未单设计时器的控制、调度、封装和测量开销。

CUDA 提交/等待一列包括提交与已有同步时 Python 调用的墙钟。H2D 和 D2H 单列实际拷贝 API 的调用时间，内部也可能等待。此处没有单个 GPU 核的事件计时。稳态所有档的静态材料上传、设备工作区新分配、D2D 和驻留世界拒绝计数均为零。[材料设备链](../../src/phymeo/backends/_tyx_world_contact_engine.py) · [逐世界材料和读回](../../src/phymeo/backends/tyx_world_contact.py)

## 下一处可验证的改动

优先细分并优化 `ClothLinkContacts._witness` 的单姿态调用。当前每次由 `CollisionMotion(ends)` 和 `CollisionMotion(triangle)` 构造查询对象，再调用 `sample(0)`，其中包括有限线段–三角面的精确最近点搜索和双侧材料见证构造。现有阶段计时覆盖这一整段，不能区分对象构造与候选枚举各用多少。后续可在这个入口验证静态专用实现，保留间隙、法向、材料权重、并列最近点、退化拒绝与完整状态 SHA。分离布面也需要向上层发布实际几何间隙。[查询构造与采样](../../src/phymeo/geometry/_capsule_triangle_sweep.py)
