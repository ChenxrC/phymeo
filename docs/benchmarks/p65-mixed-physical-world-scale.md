## 物理窗口与对照

每四世界单元有一块真实受力布与棱柱连杆、一颗自由球、一对分离的布与连杆，以及带一个子步驱动延迟的滑轨。W16 有四个相同几何单元，登记键非连续且无重叠。单元间改变外力和滑轨目标幅值，四步内反转驱动方向。自由球质量 2 kg，从 z=2 m 静止起步，重力为 −8 m/s²。受力布与杆沿用 RD-PRISMATIC-LINK-STEP 的原面积、材料与三个节点地址。初始正开距 3/32 m、层宽 1/8 m、压缩 1/32 m，在两个积分端点各产生 1 N。另一根杆抬高 0.5 m，保留整套动力学。

每窗 h=1/256 s，连续推进 4 个物理子步。每个计时窗前，两个实现都在窗外复位完整原状态和延迟历史。窗内提交各自的真实控量和外载，推进物理，再按同一世界顺序取所有接受标志、完整材料审计与完整状态。复位、对照、轨迹序列化和 SHA 均不计入壁钟。独立原接口是每个球/滑轨各自的 `TyxWorldBatch` 和每对布/杆各自的 `TyxWorldContactBatch`，逐世界顺序调用。合批入口在同一个 `TyxBatchedScene` 中分别调度常驻运动组与材料接触组。

资格组另行调用原 HOST 的 `RigidSemiImplicitSolver`、`DrivenRobotProgram.stepper` 和 `CompliantClothContactProgram.stepper`。它们逐步给出球状态、延迟驱动力与历史、三个节点和关节的状态。原 HOST 接触报告的各积分点力按其真实节点权重重建。独立比较原输入的外功、动量与支座冲量、动能增量与三种功。单独一次把首个受力世界的材料容量降到 1，要求 2 时保留其上一帧，另外 15 个世界继续推进，随后局部复位布/杆和延迟滑轨，恢复容量到 2 并重放。

## 实际接触与精度

W16 各受力世界的首步均为 2 N。第 4 步的四个中点法向力分别为 1.972708、1.971821、1.970902、1.969924 N，四个分离世界保持 0 N。随异载改变，四步的有效端点总数依次为 8、6、5、5，原 HOST 程序给出相同的端点参数。完全对称单元仍使用两个积分点，初始每节点承担 −2/3 N，杆承担 +2 N。第一次 W16 验收曾错误假设整个窗的各活跃世界都始终用两个积分点。保留原输入，把后续每步与实际 HOST 的积分点数、位置参数和力核对后，通过了该窗。

W16 四步所有球、滑轨和材料节点与原 HOST 的位置最大差为 2.72×10⁻¹¹ m，速度为 3.31×10⁻⁹ m/s，力为 2.04×10⁻⁷ N。使用原 HOST 位移与原始输入独立复算的外功最大差为 5.03×10⁻¹² J。功与动能账的最大残差为 1.44×10⁻¹¹ J，动量账为 4.66×10⁻¹⁰ N·s。阻塞的材料世界保留上一份审计和状态，15 个邻居照常推进。只复位该布–杆和一个滑轨后，重新放行的轨迹及被清零的延迟历史逐项复现。

在各自的设备上，合组与分开推进的全部接受标志、真实积分点记录、力、功、状态、受控量和历史逐帧一致。所有 CUDA 计时窗的完整 SHA 都与同档 CUDA 资格组相等。interpret 与 CUDA 的完整 SHA 不同。例如首步第二积分点的相对速度输入第 6 列在 CUDA 为 −0.009114583022892475 m/s，在 interpret 为 −0.00911458395421505 m/s，相差一个 FP32 ULP。两个后端各自通过原 HOST 物理误差检查。[真实资格](../../tests/scale/test_mixed_physical_scale.py) · [独立求解器与输入](../../tests/scale/mixed_physical_cases.py)

## 设备路径和重复次数

每个非空组合每物理步实际提交一个常驻运动核，以及两组“准备材料相对速度、计算接触层力、分配两侧受力并推进增量”的 6 个材料核。HOST 负责入口/中点和终态几何、连续路径、能量检查、完整审计发布。每轮 7 个计时窗合计推进 28 个物理子步。W4 和 W16 的合组都执行 196 个真实 CUDA 核，逐世界路径分别执行 392 和 1,568 个。两种布局的稳态 D2H 相同，W4 为 19,488 B，W16 为 77,952 B。合组 H2D 分别为 20,384 B 与 81,536 B，逐世界为 20,160 B 与 81,312 B。两边稳态都没有重建材料工作区或新增设备工作区分配。未单独计量 HOST 各个几何算子。[场景事务](../../src/phymeo/runtime/batched_scene.py) · [材料求力和缓冲](../../src/phymeo/backends/_tyx_world_contact_engine.py)

每档每轮一个新进程，两个工作区同机交替。先保存一个首窗，再做两个预热窗、七个计时窗。每个窗都转换为相同的物理输出。吞吐为七窗的已接受世界子步数除以对应总壁钟。第 1、3 轮先 W4 后 W16，首窗合组先行。第 2 轮倒序且首窗分开推进先行。每个进程内后续窗交替先后。首窗时间、复位耗时和每窗设备计数保存在 JSON 中。这里的速度比在两个 Phymeo 物理布局之间测得。[可执行计时](../../scripts/benchmark_mixed_physical_windows.py)
