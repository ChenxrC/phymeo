## 同一输入与两种读数

每张三角面有三个 1 kg 节点，两面彼此独立，只通过接触作用。原位姿、共同漂移、上侧 −0.5 m/s 入射和 EE 的轴循环旋转逐分量与对应已归档 Phymeo 首帧核对。重力、结构刚度、材料阻尼、摩擦和气动项为零。Newton 以 3 次 VBD 迭代推进，每个已接受时刻下载六个节点的真实 `particle_q` 和 `particle_qd`。动力学进程直接使用 Newton 与 Warp，Phymeo 数据仅从原 JSON 读取。代表第 41 步的实际 CUDA 活动包含顶点–面与边–边检测、3 次 `accumulate_self_contact_force_and_hessian`、3 次 `solve_elasticity` 和一次 `update_velocity`。

相互作用半径为 1/16 m，Newton 的额外检测宽度为 1/32 m，因此搜索半径为 3/32 m。接触系数均为 128 N/m。两套程序的离散法则有差别。Phymeo 用线性层力推动半隐式粒子步。Newton 的法向律在距离小于 1/32 m 时进入对数势分支，对应力幅值为 128×(1/32)²/d，直到更小的二次延拓区。本批两条 Newton 轨迹都进入了对数分支。接触几何相同仍可产生不同峰值与恢复速度。

Newton 的公开 `CONTACT_F` 不提供软体自接触力。112 个物理步全部结束后，诊断程序按保存的 113 个已接受位置和前一时刻的位置重新构建候选，用同版本原生色分组力/Hessian 核在独立输出缓冲中重算六个节点的瞬时力。已有物理轨迹先保存，其求解过程不受诊断 refit 影响。VT 按三角材料权重和顶点分配正反力，EE 由两条有向记录分别作用于各自的边。独立标量法则与权重重建的节点分量最大相差 2.36×10⁻⁷ N。表中的 ΔP 直接由上侧节点的质量和初末速度得到，力积分为从第 0 到 111 步的已接受状态诊断值乘 h 后求和。原生各次非线性迭代的内部累计接触冲量没有作为公开量输出。[Newton 驱动、逐状态测力与校验](../../tests/reference_newton/dd/impact_window.py) · [已审计的原生取样入口](../../tests/reference_newton/dd/newton_runner.py)

两引擎的初始总动量相同。Newton 的 VT、EE 全窗最大总动量偏差分别为 1.53×10⁻⁵ 和 6.10×10⁻⁵ N·s，末态系统动能相对初态分别少 0.013981 和 0.017088 J。Phymeo 存档 CUDA 的动量偏差分别为 5.96×10⁻⁸、7.45×10⁻⁸ N·s。Newton CPU 与 CUDA 的完整 113 帧节点位置和速度逐分量相同。EE 的逐节点诊断力也相同，VT 诊断力的最大设备差值为 5.60×10⁻⁶ N，沿入射法向的合力峰值相同。

每个进程将 `solver.step` 加显式同步、状态读取、独立力计算及读取分别计时。本批单进程的 CPU 物理步中位数为 VT 0.504 ms / EE 0.509 ms，CUDA 为 1.028 / 0.860 ms，首步可能包含模块编译。不同引擎的应用吞吐未在本窗口计量。

## 复现

在装有 Newton 1.7.0、Warp 1.17.0 的独立解释器运行。每个案例和设备使用单独进程及新的输出路径。例如：

```powershell
& $newtonPython tests/reference_newton/dd/impact_window.py --device cuda:0 --family EE --phymeo-receipt $frozenEE --cache-root $warpCache --out $freshJson
```

四组原始 JSON 含全部节点状态、候选、权重、逐节点力、每步动量、实际 CUDA 核、阶段时间和对应 Phymeo 输入文件 SHA。收据保存在 `artifacts/p65-night-newton-dd-impact-20261104-01/`，独立复核的 `comparison.json` SHA256 为 `ca29dd29c035d3f6bcfa62ff34212c6e7b8758f9c1f9a2a9d992485ecaa4c99d`。
