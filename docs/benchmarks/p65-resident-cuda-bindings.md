# W128 每步状态发布的 CUDA 参数绑定

在固定 W128 自由飞行窗口中，Phymeo 的两套已提交状态与候选状态每步交换一次。基线调用同一个 TYX kernel 句柄。它的复用缓存按调用句柄及编译配置索引，同一项保留上次的设备参数。上次源缓冲在下一步成为目的缓冲，设备指针随之不匹配。[原 W128 物理、冷暖与 Newton 合同](p65-w128-observed-free-fall.md)

初次剖析绑定 Git `f9bd708` 的原始源码。三个 32 物理步追踪窗分别检查到 **32 次错配、32 次重建**，两个方向各占 16 次。实测重建本身为 2.738 / 2.443 / 2.427 ms，错配检查另为 0.492 / 0.332 / 0.308 ms。两项合计占整窗 25.5%–27.1%，超过预先设定的 10% 门槛。探针同时计量实际核提交和方向，并将每步位置与线速度逐比特对照上批保存的 Newton 数据。探针的主机计时与正式未插桩配对分列。[绑定与实际出步探针](../../scripts/profile_resident_launch_binding.py)

现在两个缓冲方向分别使用一个由同一物理函数构建的普通 TYX 调用句柄。当前工作区及当前步长仍交给原运行时检查；同方向变更步长时会重新绑定。控制包只改变既有设备缓冲中的数值。解释模式继续走原句柄。这样保留了普通调用的设备校验、原生提交计时、同步、逐世界接受标记、交换前失败的恢复以及状态所有权。新追踪窗各为 **32 命中、0 重建**。专项在真实 CUDA 上改变步长和外力，检查每次实际物理输出，确认原生提交计时正常捕获两步。下载故障、局部恢复及关闭后新建工作区的独立查验也通过。[物理核](../../src/phymeo/backends/_tyx_world_kernels.py) · [缓冲切换](../../src/phymeo/backends/tyx_world_batch.py) · [输入变化与事务回归](../../tests/scale/test_resident_launch_bindings.py)

## 同进程旧 / 新配对

每个独立进程建立两个各自推进的 CUDA 工作区。旧工作区载入冻结 `f9bd708` 的 `TyxWorldBatch`，按原样对两个缓冲调用同一入口；新工作区使用两个普通句柄。每个世界从上批 128 个异构初态之一开始，应用每步读齐所有六个 FP32 分量。双方各先执行一步和五个 32 步预热窗，再做 20 个正式 32 步窗，逐窗交换执行次序。表中速度按 81,920 个已验证世界步除以正式窗口总时长。[同进程对照驱动](../../scripts/benchmark_resident_launch_bindings.py)

| 会话，初始顺序 | 旧 p50 / p95 ms | 双绑定 p50 / p95 ms | 旧 / 双绑定世界步每秒 | 双绑定更短 |
| --- | ---: | ---: | ---: | ---: |
| 1，旧入口 | 11.213 / 14.587 | 7.187 / 8.916 | 345815 / 540391 | 20/20 |
| 2，双绑定 | 10.748 / 12.218 | 7.272 / 8.971 | 371192 / 535388 | 20/20 |
| 3，旧入口 | 10.401 / 11.765 | 6.885 / 7.982 | 384986 / 582759 | 20/20 |

60 个配对的双绑定窗口均更短，各会话中位耗时降低 35.9%、32.3%、33.8%。两个工作区的逐步接受、物理核数、强制同步、状态/标志字节和完整输出均相同。每轮都对冻结 Newton 原始轨迹检查初态、冷步、暖身和正式窗口。

## 新的 Newton 1.7.0 直接对照

在同一 RTX 4060 Laptop 上由两个引擎各自重新建模。每次使用隔离解释器和空的指定框架缓存目录。初态、力、离散步长和公开应用六列与原 W128 实验相同。计时涵盖求解器、同步、下载、世界顺序、逐值解析核验和应用输出。新测第三轮 Newton 的应用吞吐高 0.81%，前两轮 Phymeo 的应用吞吐较高。这些是无接触、逐步发布全部球状态的结果。
