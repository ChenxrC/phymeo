# G1 世界内碰撞配对的存储、隔离和 GPU 查询成本

2026-11-04，`WorldCollisionWorkspace` 在 64 个共址的四球世界上只存储 384 个配对槽。正式 W32 同输出对照中，每秒可接受的世界查询数三次均超过原逐世界调用的 1.25 倍门槛。W1 有两轮延迟回退超过 10%。原 `CollisionWorkspace.detect` 保持默认，新的分区入口由调用方选择。[实现](../../src/phymeo/geometry/batched_collision.py) · [阶段任务卡](../superpowers/plans/2026-11-03-p65-next-parallel-dispatch.md)

## 存储和结果归属

冻结四球半径 1/8 m，各世界的 x 坐标都是 0、3/16、2、4 m，重复使用局部刚体、形状及材料编号。每个世界返回 6 个诊断行和 1 个接触。按局部刚体 0 到 1，间隙为 −1/16 m，法向为 +x，两侧见证的 x 为 1/8 和 1/16 m。把指定世界第二个球移至 5/16 m 后，只有该世界的接触消失。扩大报告距离时，同一对的间隙为 +1/16 m，两侧 x 为 1/8 和 3/16 m。三对独立进程逐一比较了世界键、完整基线与留出观测、复原结果和扩大距离后的见证，W1 和 W32 的五项一致。[冻结输入和见证断言](../../tests/scale/cases.py)

W64 的 HOST 与 CUDA 表均实测 384 行，每行 3 个 int32，GPU 表占 4,608 B，另有 384 个 int32 分类标记。单次调用的 TYX 运行时记录 2 次 kernel，工作区执行 1 次显式同步，读回 7,680 B。上一阶段完整全局诊断另含 32,256 行跨世界过滤结果。此次两个被计时的入口都输出每世界 6 行，跨世界行数为零。[G1/G5 测试](../../tests/scale/test_partitioned_collision.py) · [上一阶段完整诊断](p65-g1-world-isolation.md)

G5 中，世界 14 的候选容量为 0 时报告需要 1 个槽，并保留上次接受的结果。世界 3 同时完成运动查询。恢复容量后，两者均与独立查询一致。分别在分类提交和读回位置注入两轮 GPU 故障后，当次批次均未发布，后续查询重建设备引擎后恢复。空世界、总配对为零、异构组、重排、重复键、总容量与晚到的窄相错误也有独立断言。新增专项 HOST 12 项、CUDA 设备组 5 项通过，其中零配对要求设备提交为零。原入口相邻 HOST 20 项、CUDA 3 项通过。[事务及设备故障断言](../../tests/scale/test_partitioned_collision.py)

## 三轮配对计时

受测提交为 `6a8846c3a1a64b0b370e3b33b5160637ae0f9bbd`。机器为 Windows 11、NVIDIA GeForce RTX 4060 Laptop GPU（8,188 MiB，驱动 566.07），Phymeo/TYX 0.1.0a0、Python 3.12.14、NumPy 2.5.4。串行布局为 W 个工作区各执行一次查询，分区布局为一个工作区执行一次批查询。六个独立 Python 进程按串行/分区、分区/串行、串行/分区启动，每个进程各自新建 W1、W32 工作区，复用已有磁盘编译缓存。每个配置先预热 5 窗，再测 20 窗，每窗连续完成 32 次全世界查询。端到端墙钟包含边界构建、同步、读回、HOST 窄相和全部行发布。稽核见证、改变状态、显存查询和文件输出位于窗口之外。[测量入口](../../scripts/benchmark_worlds.py)

| 轮次 | W | 串行 p50 / p95（ms/窗） | 分区 p50 / p95（ms/窗） | 串行 / 分区（世界查询/s） | 分区相对串行 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 16.720 / 18.335 | 15.871 / 17.608 | 1,914 / 2,016 | 延迟 −5.1% |
| 2 | 1 | 15.154 / 16.522 | 16.753 / 21.579 | 2,112 / 1,910 | 延迟 +10.6% |
| 3 | 1 | 16.126 / 17.537 | 18.262 / 19.639 | 1,984 / 1,752 | 延迟 +13.2% |
| 1 | 32 | 552.908 / 597.133 | 298.548 / 327.157 | 1,852 / 3,430 | 吞吐 1.852× |
| 2 | 32 | 573.393 / 627.057 | 298.543 / 337.120 | 1,786 / 3,430 | 吞吐 1.921× |
| 3 | 32 | 565.870 / 599.247 | 303.002 / 322.279 | 1,810 / 3,380 | 吞吐 1.868× |

吞吐以每窗 `W × 32` 个已接受的静态世界查询除以 20 窗时长的中位数。W32 每个实测窗中，串行/分区的真实 CUDA kernel 为 2,048/64，工作区显式同步为 1,024/32。两者都上传 98,304 B、下载 122,880 B，稳态工作区额外分配和静态重传均为零。以第 2 轮为例，宽相计数器各窗的中位耗时从 229.50 ms 降至 13.08 ms，HOST 窄相由 213.35 ms 变为 167.09 ms。各分段与端到端耗时分别计算中位数。

W1 两个入口每窗均执行 64 个 kernel、32 次显式同步，上下行分别为 3,072 和 3,840 B。只有一个世界时没有合并设备调用的空间，分区入口仍执行世界映射和事务发布。第 3 轮各窗的包络/宽相/窄相中位耗时，串行为 3.74/5.94/6.16 ms，分区为 4.03/6.60/6.76 ms。冷查询另行记录。W1 分区首次查询包含按需创建设备引擎，三轮为 251–411 ms。串行首次查询为 22–27 ms，其工作区构造另耗 234–272 ms。设备事件时长和本进程显存峰值在收据中均为 `null`。此处物理子步数为零。

每轮分别以 `serial` 和 `partitioned` 替换下列布局参数并在各自的新进程中执行。实测原始文件位于本机 `artifacts/p65-wave5-partition-20261104-01/partition-round-{1,2,3}-{serial,partitioned}/`，各含 20 个逐窗样本、校验结果、传输计数、输入哈希和退出码。第 2 轮前守卫等待其他 Python 进程自然退出，等待在测量进程之外。

```powershell
python scripts/benchmark_worlds.py --engine phymeo --device cuda:0 --worlds 1 32 --layouts serial --warmup 5 --samples 20 --window 32 --cache-root artifacts/g1-tyx-cache --out artifacts/g1-serial.json
```
