## 已修复的问题

CPU 和设备版本原先按整行判断位置是否修正；只要 Y 发生接触修正，就重建 XYZ 三个速度分量。在 X 为大坐标、自由 X 位移被浮点舍入吞掉时，Y 接触会把应保持的 X 切向速度清零，仍报告接受。

复现：零重力，点位置 `(1e16, 1, 0)`，速度 `(1, -1, 0)`，固定单位球中心 `(1e16, 0, 0)`，dt=0.1、一个子步。CPU FP64 错误输出速度 `(0, 0, 0)`。FP32 将 X 改成 `1e8`，CPU、tyx 解释器和真实 CUDA 同样复现。交换固定/移动的粒子与刚体也受影响。

修复使速度重建按坐标分量选择，未被约束修正的分量保留预测速度。新增粒子/刚体 × CPU FP32/FP64 四个用例，以及两个设备用例：六项先观察到应为 1 的 X 速度实际为 0，修复后通过。设备新增两项还分别在解释器和真实 C++ 编译运行通过。没有放宽物理门槛。

修复改变求解器，因此旧版设备长实验已在 CPU 着色参考 240 帧保存后停止；不把其结果当作修复后 GPU 证据。修复后真实 CUDA 全套 **688 passed**，Python 3.11/原生 pip 3.12 核心各 **577 passed / 111 deselected**；54 个包内源文件与当前源码相同，源码外新建 pip 环境的安装与联合接触 smoke 通过。CPU 完整实验及设备完整实验需要重新验证，最终状态见[验收对照](rigid-cloth-acceptance.md)。
