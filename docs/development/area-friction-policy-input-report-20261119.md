# 训练策略可从 CUDA 读取双爪对物体施加的力

2026-11-19，`codex/exp`。两个独立世界使用同一个带接触力反馈的 Torch 线性策略，各执行 35 个真实的 MuJoCo-TYX CUDA 步，每步 4 ms。两个电机的动作送回仿真。这里验收观察、动作和重置的闭环；网络权重由实验指定，策略学习和任务成功率留到后续测量。

## 策略实际收到什么

异构操作环境的 v2 观察字典增加 `area_object_contact`。形状为 `[世界数, 4, 8]`，CUDA FP32。第二维固定为第一指、第二指、支撑面、其他。每行依次给出该角色是否声明、是否使用面积摩擦定律、是否有已接受步的记录、是否有接触积分点、压缩法向载荷（N），以及物体所受世界坐标切向力的 x/y/z 分量（N）。法向列累加各点的压缩载荷；切向列按物体实际在 A 或 B 侧确定符号后相加。面积积分已包含在每点的力里。每个世界始终用自己的模型声明和接触行。

终端的 `final_observation` 保留刚完成那一步的力。若此时触发自动重置，给下一动作的 `observation` 清掉该世界的接触历史，保留角色和定律声明。正常分离的下一帧可同时读到“有已接受步的记录”和“无积分点”。一个几何接触也可能有积分点而法向载荷为零。与步末姿态拼接时，力对应刚完成一步所用的接触面及共同求出的速度。[特征字段与实现](../../src/phymeo/training/area_friction_policy.py) · [训练环境](../../src/phymeo/training/manipulation_env.py)

```python
obs = env.observation
while collecting:
    policy_input = torch.cat((command, obs["area_object_contact"].flatten(1)), dim=1)
    actions = actor(policy_input)
    transition = env.step(actions, world_keys=env.world_keys, expected_frame=env.current_frame)
    obs = transition.observation
```

## 一条连续轨迹上的检查

两边均为同一 0.30 kg 自由方块、两个独立滑动夹爪和有限支撑板。方块起始底面距板面 2 mm。两世界向上的外载分别为 0.22 N 和 0.11 N，夹紧指令分别为 0.52 和 0.38，第 24 步共同切换为张开。下表取第一指作用在物体上的力，负 z 表示摩擦抵抗向上的运动。

| 时刻 | 世界 41，法向 / 切向 z（N） | 世界 7，法向 / 切向 z（N） | 策略看到的结果 |
| --- | ---: | ---: | --- |
| 第 18 步末 | 0.46456 / −0.10994 | 0.35240 / −0.05495 | 同一个网络读到不同的接触载荷 |
| 第 19 步末 | 0.46365 / −0.10996 | 0.35154 / −0.05479 | 终端观察保留两边的夹持力 |
| 第 20 步的策略输入 | 0 / 0 | 0.35154 / −0.05479 | 仅世界 41 的 episode 重置 |
| 第 35 步末 | 0 / 0 | 0 / 0 | 两个世界已经张开，两指均无接触积分点 |

第 18 步动作使用第 17 步的力。保持夹紧指令固定、只将接触特征清零，第一指的原始动作在两个世界分别由 0.50149 回到 0.52、由 0.36652 回到 0.38。正常推进中独立比对了设备动作、策略输入、任务读取器的两指载荷及物理步回执的逐点力。自动重置当步的已重置世界用保留的终端观察和成功判据读取器核对法向载荷，下一步实际送入策略的是清零后的帧。

## 复现与边界

`tests/test_manipulation_area_friction_policy.py` 包含三个检查：上面的 CUDA 轨迹、不同摩擦系数间拒绝恢复空游标、混合定律及物体在 B 侧时的符号和掩码。后者使用可手算的张量。另有 36 项任务、旧版面积观察与训练环境兼容测试通过，五个 Python 文件通过 Ruff 和格式检查。[测试入口](../../tests/test_manipulation_area_friction_policy.py)

原始轨迹和串行命令收据在 `artifacts/area-friction-policy-input-20261119-01`。轨迹文件位于 `06-three-area-pairs-pytest/test_shared_actor_sees_load_re0/actor-trajectory.json`，含 35 步实际网络输入、动作、终端特征和下一帧特征。首版夹具的初始物体离支撑面过远，被原任务判据拒绝。第二版用原生碰撞地面，与带阻尼面积路径的能力检查冲突。最终将桌面作为第三个有限面积接触对；双爪、方块和桌面共用同一面积接触路径，求解上限保持 8 自由度。本次覆盖固定基座双指夹具，桌面在这条向上加载的轨迹中保持分离。
