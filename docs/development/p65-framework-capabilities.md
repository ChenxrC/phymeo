# P6.5 框架能力与子 agent 交付规则

状态：2026-10-29 用户明确补充。本文落实现有P6.5范围的复用性要求，不新增P7/P8，也不表示下列能力已经实现。总目标仍为[双臂递布里程碑](../superpowers/plans/2026-10-27-dual-arm-cloth-handoff-milestone.md)，实际推进点见[续作入口](p65-continuation.md)。

## 框架能力先验收，综合案例再接入

接触建立/分离、特征切换、CCD、弯曲、自碰撞及后续发现的必要共性能力，必须形成可复用的生产模块。综合案例负责配置模型、材质、目标和控制阶段，调用这些模块；不得在案例脚本中另写接触算法、按机械臂名称/阶段时间选择物理规则，或用场景坐标特判补齐框架缺口。

“可复用”指同一公开合同能被其他符合支持范围的场景调用，不承诺首版任意几何、材质、速度或规模。每个切片先声明支持域、后端与拒绝条件；调用方不必复制实现、改核心源码或访问私有字段即可替换对象和参数。有限的节点/局部平面基础保留原边界，不重新命名成通用碰撞已完成，也不为形式统一重写已验收功能。

生产算法放在src/phymeo的对应几何、约束、耦合、求解器或运行时模块，案例与渲染消费公共结果。求解器内部状态仍归其所有；统一端口负责交换，SceneStepper负责全局时间和事务。Three.js只展示真实导出结果。

## 实现子 agent 必须收到的任务单

主 agent 先确定下列内容，再派实现子 agent；不得只发送“把递布跑通”或“补CCD”。设计尚未冻结时，只派有范围的只读需求/数学推导任务，不把该产物计为实现。

1. **能力编号与依赖**：对应H1/H2/H3等总里程碑、现有可复用代码、缺口、该切片明确不支持的范围，以及接入综合案例的前置关系。
2. **接口与物理语义**：输入/输出及形状、单位、坐标系、构型/时间求值点、材料厚度、特征身份、参数机制和状态所有权；接触生命周期与缓存的试算、提交、回滚规则。
3. **支持与失败合同**：几何/拓扑/材质及速度范围、实际后端、无效和退化输入、预算耗尽、无法证明安全时的结果；不能静默漏检、回退或放宽门槛。
4. **先验收再实现的测例**：明确初值、独立参照、单位化阈值、应接受/拒绝的条件；覆盖成功、失败、边界、共享响应和后段故障。先观察新测试RED，再实现并保留证据；测试不能仅复述实现公式。
5. **文件与协作范围**：允许编辑的模块/测试/文档，不能改变的公共合同和旧回归；共享接口由主 agent 集成，只有无依赖且文件不冲突的任务才并行。资源测试与正式性能观测串行，避免污染结果。
6. **返回证据**：代码与接口说明、实际测试命令/环境/源码版本/结果、支持矩阵、剩余限制与问题目录、性能观测和接入示例。启动/未执行/超时不能报通过；主机计算不能冒称tyx设备执行。

主 agent 负责核对需求与实现、组织该独立阶段的一次fresh审阅和必要修复、运行适当集成回归，再接入综合案例。子 agent 的“完成”消息本身不构成验收；已关闭审阅不重开。新的设计/API细节按阶段冻结，不在本文预先指定尚未证明的算法。

## 每项能力的独立验收底线

以下是测例类别，具体参数、数值门槛与支持范围须在对应阶段设计中冻结；未冻结的阈值不能在看到结果后倒推。

| 框架能力 | 公共结果与边界要求 | 非递布独立测例及参照 |
| --- | --- | --- |
| 接触建立/持续/分离与特征切换（H1） | 统一候选、稳定身份、几何/材料点、接触事件和历史；几何候选不等于已施加冲量；分离后不能残留拉力/摩擦历史 | 无机械臂的物体接近/离开支撑面；不同拓扑布片沿面滑动并跨面/边。用解析间距、独立几何/KKT条件和原式载荷账本核对；重排对象/接触顺序及后段故障时结果一致或在冻结容差内 |
| 连续碰撞检测（H1） | 明确最终接受路径的插值、厚度与速度界；输出安全区间/碰撞或不确定状态，预算用尽不能作为安全；机器人旋转路径不能默认为端点直线 | 高速薄片/平面穿越；旋转连杆或边掠过布面。解析可解的TOI、经证明的包络/区间参照及独立细分交叉检查；端点不交但中途穿越、擦边、静止、初态接触、退化与预算失败必须覆盖；有限采样本身不能证明无碰撞 |
| 弯曲材料（H2） | 明确拓扑、静止构型、材质参数、力/投影/速度重建与能量语义，接入统一材料账本和事务 | 独立铰链/条带弯曲；不同拓扑网格片变形。刚体运动不产生伪弯曲响应、静止形状平衡、独立有限差分/能量和步长/网格对照；重复/退化面及非法材质显式处理 |
| 自碰撞（H2） | 拓扑邻接排除与厚度规则公开，点面/边边支持范围明确，同域双方反作用只算一次；持久缓存可恢复 | 自由折叠布片；非相邻边/面相向运动或自接近。独立距离/交叉判据、同域合力/力矩账本；邻接排除不能误屏蔽远处接触，测试顺序/网格重编号与失败恢复 |
| 控制与抓取接入（H2/H3） | 目标、限力/限速与控制history可复用；真实接触承担抓取，案例只编排阶段 | 不同物体/布参数的有限驱动单爪承重；低摩擦或不足夹持力下滑落。支撑冲量/重量与执行器功参照、饱和与失败相位记录；不靠时间跳转宣告成功 |

每个新框架能力至少用两个与双臂递布编排无关的独立小场景验证，并改变与该能力有关的对象/拓扑/参数；仅复制同一案例换名称不算。适用时覆盖刚体平移/旋转变换、对象/接触顺序、网格重编号，以及尺寸/速度支持边界。不能把有限范围合同宣称为通用准确性证明。

实际NumPy对照和tyx路径按阶段支持矩阵验收；FP32/FP64转换及误差预算公开。TYX-003的C++长期门禁仍未通过，无新依赖修复不重复压力；依赖阻塞与可继续的NumPy/CUDA工作分别记账。性能只观测，框架集成开销记性能目录，已定位tyx实现问题记tyx_flaw，未测Warp不声称差距。

后续按“缺口确认→需求与测例冻结→子 agent 实现→独立验收/审阅修复→综合接入→整体回归”逐项推进。框架能力和案例接入各自记录状态、证据路径与阻塞，不把设计稿、实现数量、单元测试完成比例换算成整个P6.5完成百分比。

框架切片验收后仍须全流程A夹取→B接布→平台放置、完整重复/步长/网格/扰动/失败对照、全局事务、同源Three.js及准确Git/CI交付。全部通过才关闭P6.5；不为补通用能力无限扩展成与本目标无关的物理功能库。

## 下一框架任务的只读需求准备

子 agent `framework_capability_brief`已完成只读代码核对，没有修改代码或运行数值测试。该结果是设计输入，不是已验收能力。随后[距离证书设计](../superpowers/specs/2026-10-29-p65-distance-certificate-design.md)已明确合同，唯一builder检查返回nothing important left；[实施任务单](../superpowers/plans/2026-10-29-p65-distance-certificate.md)已准备，产品尚未实施。

- [surface_features](../../src/phymeo/geometry/surface_features.py)已有点/三角、边/边最近点和精确KKT容差门禁；其distance不能直接视为严格距离下界。[已有距离下界候选](p65-distance-bound-candidate.md)仍无生产API。
- 现有[材料接触程序](../../src/phymeo/solvers/initial_robot_material_contact.py)仅支持初态闭合接触，[机器人平面程序](../../src/phymeo/solvers/robot_plane_contact.py)继承base的history，尚没有通用动态接触身份、侧和活动集历史。现有端口及全局事务可复用，不能把这些缺口留给案例脚本。
- 建议下一设计明确可复用静态距离证书与动态接触/CCD的接口，先验证保守几何下界。是否单独公开证书API、支持特征、权重见证归一语义、退化策略和严格舍入方式均须在阶段设计冻结，不因这份建议直接扩展公共接口或重写旧最近点API。

给后续几何实现子 agent 的最小测例要求：无机器人探头与三角板（面/边/顶点最近与零距离）；两根独立杆件（偏斜/交叉/平行/重叠/端点最近）。若采用距离证书，应验证0≤下界≤真实距离≤上界，并要求解析最优见证产生有用的非零下界，不能用永远返回0蒙混通过。独立oracle使用解析或精确凸距离参照与FP64结果的有理平方比较，不调用生产认证辅助函数。

另须测试故意非最优的可行见证、负/零/非有限权重、退化/近平行、顶点置换与两段交换、精确可表示的坐标变换、极端尺度与开方ULP边界、自有结果、失败后重试。纯几何API不拥有Scene历史；集成层用最后子步认证失败和资源退出失败检验全局恢复，保持模块边界。该阶段如只在host执行，则准确标明host FP64，不称CUDA几何。

静态证书即使通过，也只解除一个前置缺口。后续仍须冻结厚度/零距离法向、拓扑身份与特征切换、建立/分离及历史清除、布线性路径与机器人FK旋转弧的区间界，再交付实际接触生命周期与CCD；弯曲、自碰撞另按同一框架规则推进。不能因此勾选完整H1/H2或把主目标停在数学基础库。
