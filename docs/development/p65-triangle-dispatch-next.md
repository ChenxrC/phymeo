# COL2 next: public finite-boundary distance dispatch

Status: RESEARCH_ONLY / NOT_IMPLEMENTED. 2026-11-12. Read-only review of parent `3f10d5ce9bd042542bf3c4f49abd3cf23d4338c0`; parent work in progress and its untracked files were not changed. COL2 execution results belong to the parent's acceptance record, not this research.

## Decision

A small reusable next slice is feasible at the **existing CollisionWorkspace/CollisionModel boundary**, with an explicit current-pose boundary-proximity query. It can automatically select eligible sphere/capsule–triangle/mesh-facet pairs, invoke the accepted TYX finite-distance kernel, and publish typed source-bound results. This is a public library dispatch feature, not another standalone geometry example.

It is **not** safe to replace the ordinary closed-mesh `detect` branch directly: that branch also supplies solid inside/contains semantics, complete material contacts and continuous path events which COL2 does not implement. Nor is resident device-vertex ingestion a two-file extension: current resident registration/gather lacks triangle/mesh descriptors. Do the HOST-snapshot public dispatch first; keep a later resident source bridge separate. No distance result authorizes force or substitutes for the unresolved curved point-witness work.

## Small implementation contract to freeze next

Suggested public entry: `CollisionWorkspace.boundary_distances(motion, *, margin, capacities)` returning a new immutable `CollisionBoundaryDistances` result. The name and caps still need parent freeze. It reuses the workspace's model and backend rather than asking callers to supply a second arbitrary facet list. Ordinary `detect`, `last_result` and all current force consumers stay unchanged. Use a separate `last_boundary_distances` publication so an existing collision result cannot be confused with this narrower result.

First domain: one current snapshot only; sphere/capsule against zero-skin standalone triangles or original mesh facets, interpret/CUDA. Require no nonconstant `end`/turn path; reject an unsupported requested family explicitly. Open triangle surfaces and closed mesh boundaries share finite-distance mechanics, but the result never claims solid classification. Different world/body/mask/exclusion filters keep their existing meanings. Deformed triangle snapshots are allowed only through explicit new immutable coordinates and fresh binding; this is not a deformable physical-state loan.

1. Validate full model/motion/source identity and original coordinate types before upload. Build immutable snapshot binding from complete material-ordered coordinates and registration (keys/revision/vertex IDs/faces/radius/filter table); do not trust a caller-provided label alone. A separate query sequence is not a physical epoch.
2. Reuse outward shape bounds and original same-world pair filtering. For each eligible shape pair, use original triangle leaf boxes and finite axis AABB expanded by radius plus the declared nonnegative margin. Actual device BVH indices become stable `(segment owner, facet owner)` pairs through a complete source map. Exact-capacity inputs succeed; overflow fails the whole publication, with actual required counts, never truncate.
3. This first query is **threshold-limited boundary proximity**. Its candidates contain every face able to lie within the declared distance band; it does not promise the globally nearest face when all faces lie farther away. Empty face results mean no face in that boundary band, not that a closed mesh does not contain the round object. A future nearest-query mode can reuse the existing checked upper-bound selector rather than pretending proximity candidates are nearest-complete.
4. Pack the accepted COL2 schema without a HOST closest-point search. One mesh registration at a time may use one batch, with a total predeclared query budget; keep local facet identity separate from dense candidate order and from other meshes/worlds. A sphere maps to identical finite-axis endpoints. Preserve every original coincident/shared-edge facet.
5. Consume every packet row into the public pair result, retaining status, source IDs, barycentrics/axis parameter, both finite witnesses, direction availability and the complete raw packet. Require exact pair membership and `require_current` before use. `CONDITIONING`/`DEGENERATE` propagate explicitly; do not remove them before reporting success or replace them with HOST geometry. Zero distance/undefined normal remains a valid distance-only outcome. No force site or persistent material identity is fabricated. Across-facet approximate minima/ties, if exposed, must be labeled with the original engineering error domain; they are not exact manifold reduction.
6. Publish the new immutable aggregate and pending BVH layouts together only after all groups validate. Internal batch `last_packet` may already have advanced on an earlier group; keep it private and do not publish any group as the public current aggregate on a later failure. Old public result remains available but `require_current` against a new snapshot must reject it. Preserve attempted raw diagnostics separately.
7. Prefer separately owned COL2 runtime initially: it avoids coupling a COL2 sticky UNKNOWN_RELEASE quarantine to the older TyxCollisionBatch runtime close path. If sharing a borrowed runtime is chosen, parent must explicitly align both resource-owner close/quarantine contracts; do not introduce a hidden borrowed pointer by reaching through `_engine._runtime` without that review. Normal close attempts independent owned siblings and reports uncertainty honestly.

This scope gives automatic candidate production and a genuine typed distance consumer through existing public collision registration. It deliberately does not route these engineering packets into old solid/CCD result fields or contact loads. A direct replacement of `detect` is **not recommended in this short window**; it requires a separately frozen semantics/representation change.

Both backends and a public installed consumer must pass before claiming integration. Prior COL2 geometry qualification is reused, not rerun wholesale. Stop if a requested existing consumer requires signed solid penetration, CCD, curved-surface force points or resident mesh epochs: those requirements exceed this slice and cannot be satisfied by relabeling a distance.

Feasibility: the HOST-snapshot library dispatch is a reasonable next short authoring batch after a precise API/schema freeze. Full resident accepted-bank mesh ingestion plus force consumption is not safely achievable as a narrow follow-up: it adds source layouts/gather/refit/loan invalidation and physical material-map semantics.
