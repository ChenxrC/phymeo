以下历史要求中的“当前远程完整矩阵”及“准确CI通过后推进”由本决定暂时替代，历史证据不变。

2026-10-30人工排期补充：允许弯曲、自碰撞、有限夹爪模块在各自隔离工作树并行编写代码和测试。所有执行型检查、数值测试、构建与性能采样由主agent统一串行分配资源；代码完成状态记CODE_READY_TESTS_PENDING，不作为验收。当前成本交付完成后再按冻结影响集合逐项执行、修复并集成；代码先行不虚构历史RED，也不减少最终物理、事务或后端门槛。

## 选择及依据

采用“受影响集合 + 新能力完整验收 + 里程碑全量”。始终全量会重复未变更路径；只选少数 happy-path smoke 又无法验证新接触定律与全局事务。按依赖和风险选测能缩短反馈，同时保留关键证据。

本轮冻结摩擦快照的完整 CUDA 已 2307 passed / 6196.34 s（pytest，约 103 分钟，exit 0）；其中旧材料摩擦两个步长窗口分别 1206.55 s 和 1062.46 s，合计约 38 分钟。此为测试耗时证据，不是 kernel 性能归因。是否重测取决于影响路径，不能只因测试慢就移除。

## 执行层次

| 时点 | 必须运行 | 默认不重复 |
| --- | --- | --- |
| 日常小修改 / 缺陷修复 | 新增失败反例与正常对照、直接受影响合同/数学/事务测试；相关静态检查。修改设备路径则运行对应实际后端控制 | 整分支长轨迹、所有历史材料窗口、两套本地 CPU 全量、正式性能采样 |
| 一个新框架能力冻结交付 | 至少两个非递布独立场景；新功能全部必要解析/负控制/退化/变换/顺序/后段失败与 retry=fresh；新能力规定的步长/窗口/重建重复完整跑一次；选择直接依赖和消费者的旧回归；实际 interpret/CUDA 对应新功能与关键集成；源码外 wheel 新入口 | 未变的旧能力长窗、同快照实现者已完整执行并可核对的同一套件、重复本地安装矩阵；已关闭审阅 |
| 公共底层高风险变更 | 扩大到所有受影响消费者及后端；对共享积分、参与者/kernel、状态/history/事务、全局精度或依赖 pin 变化运行相应完整 CPU/设备回归。无法划清影响时升级全量 | 无关历史性能数据重采集 |
| H1/H2/H3/H4 集成里程碑、最终 P6.5 | 覆盖自上次全量以来累计变更；完整 CPU/CUDA 与相关平台/安装证据，完整物理流程、步长/网格/扰动/失败/重复验收；最终准确 SHA/CI | 相同源码快照且覆盖已满足的重复全量 |
| 纯文档 / 报告 | docs/link、diff 与相关 JSON/证据一致性 | 数值测试、设备长窗、性能测量 |

任何新失败、交叉影响或不确定依赖都先排查并扩展必要集合，不因时间预算而跳过失败、改 tol 或缩短要求的物理窗口。开发反馈时间是优化目标，不是自动截断测试的通过条件。

## 每次选测必须留一份简短清单

在该阶段已有计划/工程记录中写明：基线 SHA、最终 SHA/源码摘要、变化文件、直接依赖和消费者、选中的明确 pytest 文件/node ID、每项覆盖的风险，以及本次未跑的旧长回归与理由。用收集结果确认非零且包含必要参数；设备测试 require-device，不能把全 skip 当通过。选测报告只称“受影响集合通过”，不得称新版本整分支全量通过。

可复用证据须核对源码、相关测试/配置、依赖、实际后端和环境；如果仅修改隔离模块，应保留旧证据所属 SHA，并附依赖未变的说明。影响范围不只看 git 文件名，也检查继承、公共 helper、动态注册、输入/能力合同及调用路径。仅修改测试或计量也要重跑被修改的相应检查，但不自动使不相关物理证据失效。

实现者已在冻结快照运行的必需新功能长窗，主 agent 读取原始日志/exit/hash 后可以计入阶段证据。唯一 fresh reviewer 负责独立探针；其后源码未变，不再由父 agent 重跑相同全部长窗。审阅修复只重复受影响检查，公共底层变更按上表升级。

## 接触框架的关键选择示例

后续有限特征/CCD 切片必须有自己的精确几何或解析 oracle、端点安全但途中穿越、特征切换、预算未知拒绝、反作用/账本和最后子步回滚。不能用旧平面例代替新几何验收。

旧接触链路可按影响选择短的自动法向解析、静/滑摩擦解析、材料斜撞、多面生命周期，以及实际 FP32 与 terminal 一次施加控制，例如：

## 性能、安装及 CI

日常只验证基准脚本可运行与解析/真实执行计数正确。需要性能方向观察时用明确标注的小样本，不能替代正式分布或宣称可靠 P95。每模式 3×100 的正式计量改为新性能基线/性能优化比较/关键集成里程碑与最终交付时执行，不再是所有小切片默认门槛。相同物理和配置的有效基线可以引用并标注版本；没有新的性能结论就不为凑报告重采样。

本地默认一套 CPU 跑选定集合，第二 Python/安装环境和 Linux 优先核对该提交的远程 CI；触及平台/打包/依赖路径时增加对应本地检查。当前 GitHub CI workflow 与 required 检查保持原配置，远程仍跑其现有完整矩阵；不把本地选测改写成 CI 降级。

C++ 仅在新原生边界需要验证时跑一个有界短例；TYX-003 未修复前不重跑已知长期压力。所有正式性能仍等待其他数值与审阅探针退出，串行执行，避免并发污染。
