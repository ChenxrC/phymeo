# S4000 平侧箱夹持稳定性对照

**本例推荐面对齐后每手指令 39 N（`firm-grip`）。** 8 个此前未参与调整的工件与目标初态，分别装上左六右七、左七右六机械臂，16 组均完成抬起、运送、放准和卸载。相同工况下，31 N 面对齐完成 13 组，加试抬与恢复的 31 N 版本完成 0 组。三种控制共同产生 48 个摩尔线程 S4000 仿真回合。这批使用固定的先验参数，新增训练时长为零。[留出配对结果](../../artifacts/s4000-flat-grasp-stability-20261126/holdout-aggregate.json) · [分段运动评分](../../artifacts/s4000-flat-grasp-stability-20261126/holdout-score.json)

39 N 相比 31 N，在全部 16 对工况中都同时降低了运输段下滑和相对转角，14 对的最终水平误差也更小。两组都能抬起并运够距离，差距出现在搬运的稳定性和放置精度。39 N 是每腕正常夹持**指令值**。整组实际每腕瞬时法向力最高为左 53.2 N、右 55.7 N，最差最终水平误差为 12.1 mm。

试抬组只在 10 个回合进入过空中运输，其中 3 个达到规定的距离和高度。进入运输的 10 组，运输时间中位数仅 0.184 s，面对齐 31 N 与 39 N 分别为 1.016 s 和 0.848 s。暴露时间短会缩小累计漂移，该行的 5.4 mm 无法支持采用试抬组。整个留出集触发了 20 次恢复，观察到 9 次完成重新夹紧。三组均未在决策采样点记录到命令仍为抬起或运输时意外回桌。

恢复动作还带来了接触峰值。试抬组种子 91008、左七右六，整回合的左腕法向力峰值达到 888.7 N。回合中第 1400 个物理步的决策端点正处于重新夹持阶段，桌面附近测到左 441.3 N、右 9.0 N。全程峰值每 2 ms 更新一次，决策记录每 16 ms 写一次，因此无法把 888.7 N 精确定位到这一帧。若继续开发恢复策略，优先检验放回后何时确认箱重已转交桌面、如何对中、如何限制再接触速度和单侧冲击。已有 39 N 路径可直接用于本任务。

## 实验设计

实验对象是 6 kg 平侧箱和每腕四枚球形接触垫。两腕从侧面夹紧平直箱壁。测试复用原腕部 RGB、关节编码器、腕部合力、机械臂限矩、摩擦、重力和自由工件。三组都使用同一份先验策略参数。

| 控制 | 动作 |
| --- | --- |
| `face-alignment` | 用腕图估计箱壁法向，保持垫面与箱壁对齐。对齐后的正常夹持指令为每手 31 N。 |
| `firm-grip` | 仅将同一正常夹持指令提至每手 39 N。提前对位、放置卸载、开爪和关节限矩沿用原值。 |
| `stable-grasp` | 保留 31 N 的正常夹持指令，增加箱体相对腕部绕侧面法向转动的反馈、低位试抬及失稳后的减速或下降逻辑。实际接触力另行测量。 |

开发回合使用种子 701（原面对齐成功）和 88201（原面对齐失败），均为左六右七。独立留出预定为 91001–91008。每个初态分别装上左六右七、左七右六，并分别运行三种控制，共 48 个留出回合。成组校验同一构型的模型、初始状态、任务、目标和先验权重，同时核对交换两臂后工件与目标不变。使用 96×96 双腕 RGB，每 8 个 2 ms 物理步决策一次，最多 400 个决策。

原完整任务要求抬起、空中运输、对准、放回并卸载。成功、中心误差、朝向与停稳沿用原评分。另用记录的 XML、关节和自由箱体状态做离线正运动学，在每段离台期间测量箱体相对手腕的转角和下滑，分别报告每手接触法向力峰值、意外回桌及受控下降。未离台的回合单列；留在台面不能获得改善稳定性的评价。只有在降低滑移或意外回桌的同时保持完整取放能力，才有依据推荐替换默认控制。

逐垫法向力、台面反力和真实箱体位姿用于独立评分。控制器在动作时从腕图和机器人的本体感知估计箱体姿态、相对运动和承载状态。

## 开发回合暴露的问题

初版保护在两个场景都于 0.752 s 触发。当时两手各提供约 29 N 向上支撑，箱体倾角分别只有 0.9° 和 1.5°。报警来自箱心相对腕部约 13 mm 的下移。参考位姿采自箱子还压在桌上时，试抬又只跟踪箱子高度，两腕在载荷转移时沿箱壁向上爬。控制器把这段位移全计入滑动，两次都在进入运输前放回了箱子。[初版开发集评分](../../artifacts/s4000-flat-grasp-stability-20261126/dev-score.json)

唯一一次修订使用两个可观测事件。腕图检测到底面升高、腕力确认双方承重后，保存一次承重抓姿，并在试抬期间用编码器闭环控制两腕高度。箱体继续相对下移时，同时检查箱体是否下落、倾斜加剧或失去承载。两个开发场景随后均通过试抬，701 完成空运但最终中心偏差 59 mm，88201 在运输途中受控下降并再次夹持。两者均未完成整次放置。修订仅使用这两个开发场景，此后冻结控制器。[701 逐步记录](../../artifacts/s4000-flat-grasp-stability-20261126/dev2-701-stable-full.json) · [88201 逐步记录](../../artifacts/s4000-flat-grasp-stability-20261126/dev2-88201-stable-full.json)

完整成功沿用原任务评分。同一连续离台期间曾升高至少 35 mm、水平移动至少 60 mm。随后桌面承重至少达到箱重的 80%，两腕接触法向力之和至多 5 N。目标中心误差至多 25 mm、三维朝向误差至多 12°，同时线速度至多 0.035 m/s、角速度至多 0.25 rad/s，连续满足 0.10 s。[原任务评分](../../examples/bimanual_musa_env.py)

“运输段下滑”取双方腕部坐标下箱心相对该段起点的最大向下位移。每段要求当步正在执行运输、净空至少 3 mm 且桌面反力低于重量的 5%。换段重新取参考，未进入运输的回合留空。这个指标包含箱体绕接触点翻转对箱心位置的影响。每腕法向力峰值取该腕各接触在同一物理步的法向力之和，再对整回合取最大值。它和控制器发出的名义夹力可以明显不同。[离线评分器](../../examples/bimanual_grasp_score.py)

## 复现

在已配置 S4000 的 Phymeo 环境中，把工作目录切到仓库根目录。`PHYMEO_RENDER_LIBRARY` 指向本机构建的 Vulkan 库。从本批证据包单独解出 `src-v2` 和 `analysis` 即可使用下列命令。物理回放使用上一批冻结的腕部渲染与视觉控制源码，最终离线评分使用归档中的 `analysis/bimanual_grasp_score.py`。这两个入口也保留在仓库的 examples 下供后续开发。

脚本按种子、实际机械臂构型和控制器依次运行。相同源码与参数可以接着使用已完成的回合，中断的原始文件会保留以供诊断。每组产生场景 XML、状态与动作 NPZ、逐决策记录和逐步积分的接触统计。离线评分仅做正运动学。

```bash
python -B src-v2/bimanual_grasp_comparison.py --source-dir src-v2 \
  --out grasp-comparison --stage holdout --mode musa --device-index 0 \
  --library "$PHYMEO_RENDER_LIBRARY"
python -B analysis/bimanual_grasp_score.py grasp-comparison/holdout --require-complete \
  --output grasp-comparison/holdout-score.json
```
