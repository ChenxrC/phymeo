# 两人并行开发与测试策略

依据：[架构设计](../architecture/overview.md)。A/B 是职责代号，不是实际 GitHub 用户名；明确人员后再添加 CODEOWNERS。

## 1. 分工原则

两条纵向工作流共享物理契约。A 负责运行基础与刚体路线；B 负责柔性体与学习路线。核心协议由 A 主写、B 审阅；共享文件一次仅一个人修改。不要按“一个人写所有底层、另一个人等底层完成”分工。

| 范围 | 负责人 | 接口消费者 | 交付/审阅 |
| --- | --- | --- | --- |
| core 模型、状态、输入、能力与报告 | A | A+B | B 审阅；冻结 dtype/单位/所有权 |
| backends NumPy/tyx、包与 CPU CI | A | A+B | B 以柔体 kernel 运行合同 |
| dynamics、刚体、关节基础 | A | runtime/coupling | B 做解析解和交互对照 |
| geometry 接触 schema、基础平面/球体 | A | A+B | B 提供粒子/布料接触需求 |
| constraints 距离/弯曲、布料与软体 | B | solver/runtime | A 审阅量纲、缓存与并行写入 |
| builders 布片拓扑/面积质量/初始条件 | B | A+B 示例与场景 | A 审阅总质量、固定点、精度与静态数据所有权 |
| runtime 状态族合同/候选事务 | A | B 的粒子/刚体 solver | B 审阅姿态、角速度、力矩回滚与固定对象不变量 |
| 球形几何与球/平面法向响应 | B | A 的状态事务/能力签名 | A 审阅半径身份、精度、候选失败和包/CI 集成 |
| learning provider、数据和训练边界 | B（数学基线后） | runtime | A 审阅回退与状态所有权 |
| runtime 步进/提交/回滚/耦合 | A 主写 | A+B | B 提供柔体端口与失败用例 |
| GPU 驻留/图执行与性能 | A 主写、B 场景验证 | A+B | 首批 CPU 正确后启动 |
| tests 与示例 | 各自模块作者 | 对方审阅 | 集成场景共同验收 |

## 2. 并行批次和依赖

| 批次 | A 的独立交付 | B 的独立交付 | 汇合门槛 |
| --- | --- | --- | --- |
| M0 契约 | 状态/质量/外力/报告 + package | 独立解析参考、约束输入样例 | 共同签署 shape、量纲、错误语义 |
| M1 单域 | 积分、tyx adapter、基本平面 | XPBD 距离、链/布片 | 同一个 state + StepResult，无私有 API |
| M2 交互 | 刚体平移/旋转、接触 response | 柔体端口、材料/约束回归 | 相反冲量、力矩、状态所有权测试 |
| M3 耦合 | 快照/回退、交替耦合与子步 | 夹爪/布料交互用例与失败注入 | 耦合残差达标，失败能原样恢复 |
| M4 加速 | GPU 批处理、CPU/GPU 对照 | warm start、训练域与长轨迹评估 | 同误差预算下的总时延/回退率 |

M0 是短暂共同基线；之后用小 PR 交替集成，不长期维护两个互不兼容的大分支。B 在等待 A 的接口实现时可以基于签署的数据样例编写纯 NumPy 解析参考和失败测试。

## 3. 接口变更与跨仓库约束

- 变更 core 或接触结构：同一 PR 更新契约、双方测试与示例；不能只改消费者。
- 模块作者负责测试；对方负责审查假设、单位、边界输入，不只看代码风格。
- tyx 仅增加可复用计算能力；碰撞政策、材料或物理状态不得移入 tyx。
- tyx 变更先固定候选 SHA，运行 phymeo 下游合同；上游验证后再更新 phymeo 依赖。
- 日常开发分支使用 `codex/…` 或团队确定的短分支；用户授权推送不等于授权合并。
- 每批提交记录输入模型、命令、环境、失败/跳过与两仓 SHA，避免“我的电脑能跑”。

## 5. 首批验收用例

| 测试 | 独立判据 |
| --- | --- |
| 自由落体 n 步 | `v_n=v_0+n*h*g`；`x_n=x_0+n*h*v_0+h^2*g*n*(n+1)/2` |
| 固定点受外力 | 位置不变、速度为 0；不得出现 inverse_mass 除零 |
| 两点约束 | 刚性距离收敛；无外力时质心不变；不同质量的位移按逆质量分配 |
| 柔顺约束 | 使用单约束解析乘子检查 compliance/h²；允许非零几何伸长，以 C + alpha_tilde*lambda 判收敛 |
| 约束多步动力学 | 投影后从子步初始位置重建速度；悬挂链不会保留持续积累的自由落体预测速度 |
| 重合点 | 有确定性策略和诊断，无 NaN；不能无声伪造已收敛 |
| 平面 | 正确法向与高度；固定对象不被移动；高速限制写入说明 |
| 刚体旋转 | 主轴恒力矩离散解、世界/体坐标映射、陀螺项、单位四元数、无力矩能量误差的步长收敛 |
| 布片构建 | 三角形 +Y 朝向、无重复边、每三角形面积质量三等分、固定点不丢失质量审计信息、初始距离与实际几何一致 |
| 球形刚体/平面 | 塑性法向速度为 0、切向/自由角预测不变、固定穿透失败、球半径不被量化吞掉、长期静止接触无法向抖动、回退不得改变几何 |
| 输入/结果 | state_in 不变；修改 state_out 不影响原输入 |
| 空系统 | 返回合法空结果；tyx adapter 绕过零元素 launch |
| 回退 | 拒绝候选后从原状态开始；不同约束/平面签名先拒绝，相同物理问题不同迭代预算可重算；一次后可失败退出 |
| 学习候选独立验收 | 自报零残差不能掩盖错误运动；verifier 与物理签名匹配；候选/输入副本隔离；数学 fallback 同样验收；大基值和先下溢后放大不能误接受 |
| 粒子／刚体端口 | 同作用点 J/-J 与 r×(-J)、旋转惯量坐标系、线／角动量、每端口有效质量实测响应、固定反力 ledger、重复冲量补偿累计和双状态原子回滚 |
| wheel | 从源码树外运行 import 与最小例子；检查 import 文件确来自安装位置 |

## 6. 容差、精度与公平比较

初始数值断言采用 `abs_error <= atol + rtol*scale`；scale 必须来自场景特征长度/速度/力或解析值，不使用一个阈值混合量纲。

- FP64 解析参考的小型线性场景：起始 `atol=1e-10, rtol=1e-8`。
- FP32 tyx 与相同离散方法的对照：起始 `atol=1e-6, rtol=1e-5`，先做条件数/步长扫描后冻结。
- 约束收敛以归一化最大本构残差和迭代数验收；柔顺距离残差为 C + alpha_tilde*lambda，几何伸长单独报告。达不到就报告未收敛，不能只看最后画面。
- 长轨迹与能量不能沿用单步阈值。保守系统、耗散系统、外部驱动分开，记录外功和耗散。
- 接触切换附近不强求普通中心差分梯度通过；按声明的 fixed-active-set 或平滑模型验证。
- 减少 JIT 或 GPU 拷贝的性能收益必须计入完整 step；先预热，再报告中位数/p95、环境和误差。

这些数值是初始验收建议，变化必须附稳定性/误差证据，不得为过 CI 随意放宽。

当前 CPU 布片示例为 4×4 点、18 三角形、42 条距离约束，60 步 × 0.02 s；逐步要求 accepted、固定点不变、无平面穿透。FP64/FP32 的最大归一化本构残差均小于 1e-6，最多约 360 次串行迭代/步。这是正确性基线，不能作为高性能布料指标；后续 tyx 加速由 A 持有执行/内存、B 持有连接图/约束数值与对照场景。

`cloth_patch.py --steps` 改变仿真时长，并不承诺任意时长收敛。审阅实测两种精度在默认 400 次预算下于 frame 66 耗尽迭代；可用 `--iterations` 调整预算并重新验收，不能放宽残差后继续宣称相同精度。失败仍返回非零状态，未收敛帧不提交。

tyx 着色 XPBD 由 A 持有 runtime/缓冲/内核发布，B 持有着色互斥检查、约束公式与独立解析对照。新增验收包含同一颜色 64 条独立边、两色耦合链对照稠密线性解、距离/平面交替、数值失败回滚、空设备集合，以及与 NumPy 同物理签名的一次回退。`examples/tyx_cloth.py` 用 30 步、dt=0.02 s、16 点/42 边/8 色进行轨迹对照；GPU 阈值 1e-5，FP64 参考阈值 1e-8，不能把不同阈值的耗时当加速比。

可选 CUDA 图由 A 持有捕获/重放及 stream/数组生命周期；B 验证单轮不额外执行、变化 dt/力/模型后的重建、图与直接路径每步状态/报告一致，并注入捕获、重放和读回故障。`examples/compare_cuda_graph.py` 专门比较相同 FP32 阈值与顺序的两种执行策略；默认路径保持直接启动。

独立验收由 A 持有 Stepper 协议、能力门禁、复制及一次回退；B 持有物理 verifier、单位尺度与解析残差。两人共同确认新学习模型的物理签名和适用范围。当前自由粒子回归示例仅验证接入，无训练加速或未知材料泛化结论。

粒子／刚体端口由 A 持有索引、载荷 ledger、双状态所有权及执行实现，B 持有作用点／冲量符号、世界惯量、有效质量和独立动量审计。当前只消费已知冲量；后续由约束或碰撞模块决定冲量，并单独验收时间区间累计和跨端口耦合，不能把单端口 K 当作全局独立块。

## 7. CI 结果判定

没有 GPU 的宿主机允许明确 skip GPU 测试；专用 GPU gate 设置 require-device，缺硬件、零测试收集、全跳过都应失败。分开标注 source-lowering、编译成功和硬件执行。测试失败保留 JUnit、场景配置和种子；不得上传私钥、模型私密数据或训练集原始内容。
