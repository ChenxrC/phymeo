# PERF-002：共享刚体的串行接触与全对枚举

- 状态：结构候选，规模瓶颈未量化；2026-10-27，定位源码 `67371f9`。

## 现象与原因

[_tyx_coupled_kernels.py](../../src/phymeo/backends/_tyx_coupled_kernels.py) 中 `project_contacts`（9 行）和 `project_contact_velocities`（126 行）用一个 `tx.range(1)` worker 顺序处理粒子/球对。当前每轮枚举 Np×Nb 对，无宽相筛选。

顺序执行是为共享刚体保留确定性 Gauss–Seidel 更新，避免丢失反作用；它不是尚未修复的并发 bug。多个端口共享对象会存在交叉响应，简单改为并行写入会改变算法甚至产生数据竞争。

## 测量与后续方向

分别扫描粒子数、球/连杆附件数、实际活动接触数与批环境数；记录每轮对数、迭代数及端到端时间。不要把机器人树内响应与独立刚体更新混为同一成本。

后续候选：宽相候选集、接触岛、冲突图着色、Jacobi 归约或分块响应求解。每种方法都需要重新检查接触身份、反作用只计一次、跨端口响应、残差与确定性；当前不能宣称任意一种一定更快。

本轮保留可验证更新规则。若代表场景无法在可接受资源内完成，仅处理最小可运行规模与必要故障，再单独记录扩展限制。
