## 每个里程碑必须留下的测量

1. 环境：提交/脏状态、源码与 tyx SHA、Python/NumPy、CPU/GPU、驱动、后端、精度、线程与批大小。
2. 工作负载：模型/场景配置、对象/关节/粒子/四面体/约束/活动接触数量、固定时域、步长、迭代与容差。
3. 时间：独立冷启动与 JIT、预热后的完整 step 中位数/p95、阶段耗时、吞吐。异步设备必须同步后计时，记录同步方法。
4. 阶段：模型构建、运动学、质量/偏置计算、预测、内部材料/约束、接触、耦合迭代、验证、提交/回滚、传输与输出。
5. 资源：峰值主机/设备内存、分配和传输次数/字节；工具无法可靠采集的项标为未测，不能填 0。
6. 质量：接受/失败数、残差、物理误差、实际迭代数。记录超时/失败规模，不能只保留最快成功样本。

最低协议建议：至少 2 次预热、3 次独立热态重复，每次 100 个已接受外层 step；短模块算子可单独增加采样。冻结配置后测量，同机避免并行开发负载。完整端到端时间包含正确性门禁；可另列诊断子阶段，不得将关闭门禁后的时间当作可交付 step 性能。

冷启动需分别说明编译缓存冷/热；短稳态结果与完整物理时域报告分开。每个模块合入时先测一个小负载；全部动力学集成后再统一复测小/中/大负载和单/多环境，能运行的上限按证据记录，不预设加速目标。

## 记录和交接

每个里程碑新增一份独立测量报告（建议命名 `measurements/<milestone>-<run-id>.md`，实施时创建），引用 JSON 原始结果和对应热点 ID。合同阶段可只记录构造/校验开销，标明尚无新的物理 step，不填造吞吐量；模块阶段只测已实现的算子，完整 step 协议从可运行场景开始适用。未发现新热点也写明观察范围和限制；旧记录保留，不覆盖。大轨迹放本地 artifacts，仓库保存小型机器可读摘要、配置与复现命令。

每个候选热点写明：观测事实 → 未证实假设 → 定位方法 → 后续优化候选 → 正确性风险 → 重测条件。复制 [TEMPLATE.md](TEMPLATE.md)。只在真实分项测量后标记“已定位瓶颈”。
