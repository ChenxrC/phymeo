# P5 完整活动接触 step 的串行观测

最终产品源码 `e9ee2e75f4f64fef03ac7c26ea2ec0a207816135f34f2517eae3a294bb5e4a66`，
启动时干净提交 `7e8ae2f329fbb686474e13db679cb53956aa43a7`。
Windows 11 / Python 3.12.14 / NumPy 2.5.4，Intel Family 6 Model 183、32逻辑CPU。
[摘要](p5-full.json)和[完整900样本原始JSON压缩包](p5-full-raw.json.gz)包含来源、脚本哈希和逐子步质量。
压缩前/后的SHA256均在摘要内；gzip mtime固定为0。

完整物理实验及全部测试结束后串行测量，没有并行数值测试/仿真；文档准备仍在进行，
系统后台负载、CPU频率、BLAS线程没有控制。没有做优化，没有Warp/tyx速度对比。

每场景读取严格验证的200帧轨迹，固定取第100帧真实活动接触状态。
构造运行器，首次调用，然后2次预热、3批各100次完整step，每次恢复相同入口状态。
每个step含两个h=1/4000子步，保留生产验证/诊断；计时外再独立审计两个子步，
并与保存的两个子步及第101帧逐元素核对。所有900计时step均接受、失败0、精确一致。
这衡量固定状态微基准，不能当作连续轨迹吞吐。首次调用也不是独立进程/全冷缓存。

| 场景 | 构造 ms | 首次 step ms | 三批中位数 ms | 三批 p95 ms |
| --- | --- | --- | --- | --- |
| S2：1关节＋9布节点，9配对 | 1.024 | 329.327 | 312.586 / 298.873 / 308.876 | 349.312 / 332.803 / 346.384 |
| S3：1关节＋18软体节点/24单元，18配对 | 1.577 | 125.708 | 125.735 / 128.492 / 133.368 | 139.056 / 151.364 / 151.383 |
| S4：上述两节点域共存，27配对 | 2.062 | 1167.152 | 1123.794 / 1114.606 / 1160.835 | 1259.851 / 1294.349 / 1298.857 |

S2/S4两个子步各需12次位置sweep、1次速度sweep；S3各需1次位置/速度sweep。
S2布接触、S3软体接触、S4两域接触均在每个计时step实际发生。不能把模型/迭代数均改变的对比当线性缩放。
相反载荷、关节平衡、响应、固定点、材料域等每个样本质量保留在原始JSON，不只记录“accepted”。

每子步位置阶段中位数 S2/S3/S4 为138.254 / 31.161 / 515.631 ms，
速度阶段为10.279 / 29.837 / 41.295 ms；S4预测1.347、候选验证0.399、诊断1.983 ms。
这些是阶段墙钟，不能将不同样本中位数相加冒充完整step。
结构上每对接触重复端口/几何/质量和材料域查询的候选热点见
[PERF-006](../PERF-006-participant-point-queries.md)。下一步应先profile，再评估缓存/批量查询；本轮没有实施优化。

P3 [1/2/8自由度](p3-robot.md)和P4 [1/24/192单元](p4-softbody.md)保留各自冻结源码历史测量。
P3算法未改变；P4最终修复只改变负lambda分支，历史性能样本均nu=.3，但仍不把旧来源伪标为最终源码测量。
峰值内存、逐函数热点、分配次数、稳定步长扫描及GPU等价性能对照均未测。
