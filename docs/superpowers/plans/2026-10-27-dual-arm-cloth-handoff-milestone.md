## 目标与任务顺序

同一 phymeo 仿真中：机械臂 A 接近软布，双指闭合并夹起；A 将布递到 B，B 夹持承重后 A 松开撤离；B 搬运布至平台、放置、松爪并撤离，布在重力下由平台稳定支撑。
阶段切换既保留命令时间，又记录物理条件是否成立；失败必须报告卡在哪一段，不能只按时间播放“成功”流程。

1. **A 夹取与抬升**：有限驱动力通过摩擦/接触传给布，布离开初始支撑，在夹持期间不出现非物理固定点。
2. **A/B 共同承重**：B 先建立有效接触，两只夹爪在同一子步与同一块布联合求解；载荷不能各自单独算完再覆盖。
3. **A 释放、B 独立持布**：A 的夹持接触载荷消失后，B 能独立承受布重；显式记录滑移、脱落和碰撞事件。
4. **B 放置并释放**：布与平台产生实际支撑力；B 完全松开、离开后，布在规定驻留时间内留在平台并趋于稳定。
5. **复现与审查**：保存完整数值轨迹、接触/控制/历史记录、独立审计和失败对照，Three.js 读取相同数据。

## 当前能力与必须补齐的差距

截至 `1aa83e7`，机器人树动力学、节点端口、统一子步/事务和布料/材料阶段可复用。
但[当前组合程序](../../../src/phymeo/solvers/articulated_coupling.py)只指定一个机器人域，
[接触实现](../../../src/phymeo/constraints/node_robot.py)只有无摩擦节点/连杆球面接触；不能把现有 S4 直接改外观就称为双臂夹布。

| 前置能力 | 本案例要求 | 实施约束 |
| --- | --- | --- |
| 多机器人域 | A、B 各自 q/v、基座、执行器、夹爪关节和碰撞几何 | 通用调度器继续掌握时间和事务；域对接触只有一个所有者 |
| 联合接触图 | A/布、B/布、布/平台，以及机械臂/夹爪与环境的碰撞检测 | 每对有稳定标识、世界作用点、法/切向、同点相反载荷和广义反力；记录激活/分离 |
| 摩擦夹持 | 正压力、静/动摩擦、切向滑移，双指接触同时承重 | 不用 weld、临时 pin 或抓取后直接覆盖布位置代替夹持；控制命令不是外部无限质量轨迹 |
| 几何覆盖 | 夹爪接触面、平台面/边、布三角面和必要的边接触 | 不能只检测少量布节点而允许三角面穿过夹爪；明确几何厚度及邻接排除规则 |
| 布料形变 | 现有拉伸/剪切基础上补齐本案例所需弯曲及自身碰撞 | 允许受限材质/速度/网格，但折叠和交接不能靠自穿透完成；单独验证自碰撞机制 |
| 控制 | 两套可重复的关节/夹爪控制，有限力矩/夹持力和速度范围 | 可用预设目标和控制状态机；实际 q/v 由动力学计算，不直接写到目标位姿 |
| 防穿透与稳定性 | 夹爪闭合、交接、落台时的接触变化可检查 | 详细设计选择有界步长/子步与必要的连续检测；薄布穿透属于阻塞，不能按精度遗留延期 |
| 历史事务 | 摩擦乘子/接触缓存、控制相位、两臂与布的状态一起恢复 | 最后子步、接触和资源退出故障均须全场景回滚；重试与新实例结果一致 |

以上是为用户目标推导的能力要求，不表示已经选定摩擦离散方式、通用网格碰撞算法或机械臂型号。
初步建议用两台小型固定基座多关节臂及平行双指夹爪，新物理仍先做 CPU FP64 对照；复用 P6 已验收的 tyx 机器人/柔体/耦合执行能力。P6.5 新增的摩擦/几何/控制路径也必须说明实际后端，不能把 CPU 新功能冒称设备全链路。具体自由度、质量、行程、布材料/厚度/网格、平台尺寸和控制轨迹在开工前冻结。
不要求本案例同时加入体积软块；已有 P4/S3/S4 回归保持。

## 数值验收，独立于画面

详细设计必须先写入有单位的门槛和失败处理，再生成完整案例，不根据成功动画倒推阈值：

- **全程接触审计**：最大穿透、夹持滑移、摩擦锥/黏滑规则、相反载荷与广义反力、分离后残留拉力；各相关接触类型需有真实激活证据。
- **承重与交接**：抬升高度/持有时长、双爪共同承重窗口、A 释放后 B 独立持有、最终所有夹爪脱离后平台支撑与布的残余速度/位置。
- **机器人与能量**：动力学残差、关节限位或显式支持范围、力矩/夹持力上限；保留重力、执行器做功、摩擦耗散、固定基座与平台反力，不能把开放系统误判为总动量守恒。
- **精度和稳定性**：完整重复；步长减半、至少一种网格细化和适度材质/初位扰动。比较任务是否成功、事件时间、穿透/滑移、载荷冲量、最终布形与能量预算；不要求非光滑接触轨迹逐点与另一个引擎相等。
- **失败对照**：减小摩擦/夹持力应出现可解释的滑移或脱落；提前松 A、B 没有夹稳、夹爪/平台碰撞、迭代预算不足分别触发明确失败。不得通过固定布节点或忽略反力让这些用例“成功”。
- **联合碰撞**：除正常任务外，用小型独立测试强制触发臂/臂、臂/平台及布自身接触；正常任务无碰撞不构成碰撞算法验收证据。
- **事务**：在双臂共同持布阶段和最后子步注入数值/资源故障，两臂、布、控制状态和接触历史共同恢复。

这些门槛证明的是冻结场景与公布扰动域，不是任意机器人、材质、速度与复杂碰撞的普遍准确性。
当前 P5 的节点/球门槛和旧场景约 0.145 m 步长敏感性不能直接沿用为本案例的精度验收。
新案例的支撑切换、滑移与最终落台精度不能仅登记遗留后宣称通过。

## Three.js 回放交付

用户已经选择先离线完成真实仿真，再三维回放，不要求首版实时操控求解器。
渲染器只消费仿真导出的机器人位姿、布节点/拓扑、接触事件与指标，不重新模拟另一套物理。
基于 [Three.js 官方 API](https://threejs.org/docs/)提供网格显示、三维相机与操作；依赖版本/锁和构建方式在实施计划中固定。

- 显示 A/B 两台机械臂、真实夹爪、软布、平台；支持旋转、缩放、全局/交接/夹爪/落台视角。
- 播放/暂停、前后逐帧、时间轴、阶段跳转，明确物理帧/子步时间；审计模式关闭插值。
- 接触点、法向/切向力或冲量箭头、接触对象筛选、力矩/夹持力和滑移曲线，选择一个事件可定位到源记录。
- 力与冲量分别标注单位和时间窗口。位置修正载荷 kg·m 不能直接画成 N：如换算等效冲量/平均力，明确除以 h / h² 的离散意义，并避免与速度冲量重复计数。
- 显示求解质量、成功/失败原因、配置/源码/依赖与轨迹哈希。渲染用 FP32 上传时披露转换误差，原始仿真证据保留 FP64。
- 端到端测试核对显示节点/位姿/箭头和数值来源；实际浏览器验证控制和可见性，渲染帧率不作为物理求解速度。
