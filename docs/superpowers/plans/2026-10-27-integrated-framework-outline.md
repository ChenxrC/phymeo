## 三、路线选择与建议范围

可选路线：

- 继续增加专用联合 solver：首个演示改动少，但每添加状态族都重复事务和耦合逻辑，难以验证可替换性。
- **建议：统一合同后做最小纵向闭环。** 先把已验证刚柔场景迁移为第一个消费者，再分别加入机器人和体积软体。初期接口工作较多，但每个新增模块均可独立验证。
- 以外部 MuJoCo/Newton 驱动主仿真：可快速看到场景，但不能证明 phymeo/tyx 内部框架成立，和独立实现方向不符。

以下是实施者建议，需要在各子系统设计中细化，不能写成用户已经指定了某种算法：

- 机器人首版：固定基座、树结构，先旋转/移动单自由度关节、直接关节力矩/力输入；以两连杆建立解析/对照基线，再用小型多关节链验证组合。浮动基座、闭环、腱、多种复杂执行器后续独立扩展；关节限位若首版不实现必须显式拒绝相关配置。
- 机器人数学：参考公开的 RNE、CRB 及质量矩阵求解路线，独立实现；小规模稠密参考可用，不先优化稀疏/批处理。不把 ABA 等其他路线冒称为 MuJoCo 当前默认实现。
- 布料：复用现有距离/剪切 XPBD，先完成正式适配；弯曲、自碰撞另行排期。
- 体积软体：建议先一种四面体弹性模型，例如 StVK 能量、集总质量和小稳定步长积分，用受限变形场景验证。材料/积分选择在软体子设计中冻结；若选择 XPBD 体积/应变路线须明确其能量或约束含义。不能仅加几条边弹簧就宣称完成体积弹性模型，也不承诺高阶材料精度。
- 接触：首版机器人连杆可使用球形附件，与布/软体节点交互；真实关节响应必须成立。完整网格面接触、摩擦、CCD 后续扩展，具体限制见 [GEOM-001](../../legacy-issues/GEOM-001-discrete-vertex-contact.md)。
- 学习求解：保留能力声明、候选验证和数学回退入口，使用确定性假 provider 验证合同；不在本轮训练真实 AI 加速模型。

MuJoCo 数学与对照语义依据：[官方计算说明](https://mujoco.readthedocs.io/en/stable/computation/index.html)。对照前须匹配坐标/四元数、惯量、重力、执行器、积分与约束；不同接触模型的轨迹差不能直接判作其中一方 bug。

## 四、统一参数和耦合合同

以下名称是候选职责名称，尚未存在的类/文件不得标注为已实现。P1 冻结具体签名和数组形状，避免提前制造空接口框架。

| 对象 | 职责与内容 |
| --- | --- |
| Scene/Model | 只读拓扑、质量/惯量、关节、材料、几何、域 ID、版本和物理签名 |
| State | 每域自己的表示：粒子 x/v、刚体位姿/速度、机器人 q/v、软体节点及必要材料内部量 |
| Inputs | 外力、力矩、关节驱动、边界输入；单位/坐标/作用区间明确，不混用力与冲量 |
| SolverSettings | dt、子步、容差、迭代预算、特征尺度；算法专属设置用有类型配置，不用任意字典静默忽略字段 |
| BackendContext/Workspace | 后端、dtype、设备、资源所有权、生命周期；初版可逐步分配，不要求持久缓存 |
| StepResult/Report | 每域候选、联合接受/失败、原因、残差、冲量、迭代、后端及可选测量 |

模型参数、状态输入和执行资源分开；拓扑改变要重新验证/编译，不能复用过期参数。不同精度或设备互操作仅在显式适配后允许，不静默转换或回退。

### 求解参与者最小责任

1. 声明状态族、物理能力、后端/精度、历史需求和物理签名；检查配置与拓扑。
2. 创建含物理状态、乘子/warm-start/材料内部量和必要缓存的事务候选；无隐藏不可恢复状态。
3. 在指定子步区间预测自由运动并提供内部材料/关节求解，不自行额外推进整个外层 dt。
4. 查询作用点位置、速度、所属对象与映射；可由机器人雅可比或软体节点权重提供。
5. 提供力/冲量到候选运动的响应，包括共享对象的交叉项；机器人用质量矩阵求解与雅可比，不只返回单连杆质量。
6. 支持在同一子步候选上施加增量；力、位置乘子等效冲量、速度冲量分别记账，反作用只执行一次。
7. 返回独立可检查的残差/不变量和失败原因；全局通过才能提交，否则恢复所有参与者。

端口应统一世界作用点、方向、单位、时间区间和稳定 ID；各域内部数据无需拼成同一个扁平数组。机器人多接触的 K_ij = J_i M^-1 J_j^T 不能被当成互不相关的自响应块。软体节点端口与机器人端口须符合功率/冲量对偶关系。

每个跨域接触只有一个调度/响应所有者。参与者的内部约束与跨域接触分开，防止机器人和外部耦合器各解一次同一接触。法向、作用点和时间步必须一致。

全局事务包括所有子步：后段子步失败时，双方/多方状态和历史一起恢复。设备故障不得把 CPU 未声明的补算伪装为 GPU 成功；配置错误与数值未收敛保持可区分。

### 建议模块边界

- `core/`：有类型模型、状态/输入族注册、能力、签名、报告。
- `runtime/`：多域候选和生命周期、统一调度、提交/回滚；由一个维护者持有共享文件。
- `coupling/`：端口合同、响应算子、跨域约束组织与载荷记账。
- `dynamics/`：机器人空间代数、树运动学、质量/偏置和响应计算。
- `solvers/`、`constraints/`：布料和一种体积材料的具体算法；不把物理政策放入 tyx。
- `backends/`：相同物理合同的 tyx 内核与资源适配；`builders/`：场景模型构造。
- `validation/`、`experiments/`、`tests/`：独立物理验收、完整实验、性能记录。

P1/P3/P4 子设计应提前冻结场景尺寸、材料、速度范围、时域、步长、精度、迭代预算和量纲化阈值，再据此实施，不能看到结果后调整门槛。S4 可采用先后接触布和软块，不强求复杂抓取或同时多物体碰撞；但同一运行必须包含三种动态状态与真实交互，不能仅创建对象不让其参与。

上述 S4 简化边界不适用于用户新增的 S5。S5 需要真实多关节机械臂及双指夹爪、非零重力下摩擦承重和交接、布料/平台接触；不能靠固定布节点、直接覆盖布轨迹或动画绑定实现抓取。该案例所必需的摩擦、面几何、弯曲/自身碰撞及防穿透能力从后续研究项提升为 P5.5 的验收前置条件；具体几何支持范围、材料、控制与量纲化阈值在详细规格中冻结。单个成功案例不证明任意复杂碰撞均受支持。

本轮完成条件：上述场景 CPU 参考均实际运行；S2 机器人—布料、S3 机器人—体积软体、S4 三类共存均完整执行真实 tyx CUDA FP32 并与参考对照。允许主机调度和独立验收，但相应机器人、布/软体与耦合的核心计算必须实际在设备执行，不能用分模块测试代替 S4 完整场景。还须满足：新 solver 接入不改调度器；每域状态/历史与设备故障回滚验证；unit/integration/packaging/CI 证据；可查看真实轨迹；每阶段性能记录与统一最终基线齐备。

不以动画、接口数量、测试数量或单次不崩溃作为唯一完成证明。未支持的功能明确报错，未实现的路径不记为完成。

## 七、单元、集成与性能测试

- 合同：shape/dtype/单位/坐标、空域、非法拓扑与材质、未支持关节、跨域参数匹配、对象别名和生命周期。
- 机器人：单摆/两连杆解析或独立参考、雅可比有限差分、正定质量矩阵与求解残差、驱动力和端口冲量响应；固定基座会交换外界动量，不能误报整个系统守恒。
- 柔性体：原布料回归；四面体参考体积/质量、静止无内力、刚体平移/旋转不产生应变、能量梯度/内力、加载响应、退化/倒置拒绝。
- 耦合：同一点相反载荷、力矩与关节广义力、共享连杆/节点的交叉响应、反作用只计一次、一次时间推进、候选验证及末子步/后端故障原子恢复。
- 后端：同算法/次序/参数的 FP64 与 FP32 误差预算；同后端重复；编译成功和实际设备执行分别记录。不同接触模型的跨引擎比较按物理差异解释。
- 工程：Windows/Linux、Python 3.11/3.12、uv/pip 核心矩阵、源码外 wheel 安装；MuJoCo 对照依赖独立锁定。GPU 按实际可用机器执行，不把本机证据写成已部署云端 GPU CI。
- 性能：每阶段采用[统一测量协议](../../performance-bottlenecks/README.md)；新增热点与既有热点的变化都记录，集成后统一复测；分项成本未测时不猜百分比。

基准记录模型/源码/依赖 SHA、硬件、配置、原始数据与命令。测试失败保留证据；性能测量失败也记录，不能隐藏不可运行的规模。

## 九、进度口径与后续阶段

每个模块按 0% 未开始、25% 合同与独立用例、50% CPU 最小实现、75% 集成/后端通过、100% 全部验收及证据提交来展示；这是完成检查点，不是工时估算。总体比例只在实施任务和权重冻结后计算，不把文档建立当作动力学完成。

本轮之后按证据排序：

1. 精度/稳定性：处理 NUM-001 步长敏感性、接触事件与材料/积分误差。
2. 性能：根据实测热点选择持久工作区、传输/同步、响应求解、并行接触或批环境；同质量预算复测。
3. 几何/物理范围：面接触、CCD、摩擦、自碰撞、弯曲与更多机器人关节/执行器。
4. AI：先尝试受验收约束的 warm-start/预条件，再评估真实代理求解器；误差、回退率、端到端收益共同验收。

除已明确授权插入的 P5.5 外，上述后续方向不能自动变成本轮新增工作。没有指定新的截止时间或工时承诺；当前长程续跑按最新目标队列先完成 P3–P5 工程验收，再接 P5.5，不自动进入 P6 或 AI 训练。
