# P1/P2 Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可扩展的统一合同与分阶段运行器，并以现有 NumPy/tyx 刚柔场景和真实端口/自由运动消费者验收。

**Architecture:** 注册状态合同负责类型、字段和不变量；SceneProgram 提供分阶段候选工作区；SceneStepper 拥有子步、迭代门禁和全局事务。历史显式放入 SceneState，资源退出后才能接受。

**Tech Stack:** Python 3.11/3.12、NumPy、固定 tyx、pytest、uv/pip；不新增必需依赖。

**Spec:** [P1/P2 设计](../specs/2026-10-27-p1-p2-runtime-design.md)。

## Global Constraints

- SI、Y-up、xyzw；同场景同精度；NumPy FP64 与实际 tyx FP32；不复制 Newton 源码。
- 只做 P1/P2，不实施机器人/体积材料/AI 训练，不开展性能优化。
- 输入/模型不得被实现修改；完整外层状态和显式历史原子提交，资源关闭失败不能成功。
- 物理与执行参数分离；不能用旧整帧 step 包装代替新运行器阶段调度。
- 每个切片测试、记录、提交推送；不合并主分支，不发布软件包。
- 用户补充：tyx 测试发现的依赖实现性能/能力问题登记到 [tyx_flaw](../../../tyx_flaw/README.md)，提供可复现证据供 tyx agent 接手；区分集成开销与依赖缺陷，Warp 未测不作差距结论。
- 沿用已验证 checkout/工具链并新建专用分支 `codex/p1-p2-runtime`，基线 `bf6c41a`。

## Review Focus

- 第三方族使用 q/v 或额外历史字段时，不得被 position 假设、浅复制或漏校验破坏（T1/T3）。
- 多个点共享刚体/重复索引时，不能丢交叉响应或重复冲量；不同作用点不得伪称守恒交换（T2）。
- 模型/签名/历史 schema 绑定后改变，必须先拒绝，不能复用旧参数（T1/T3）。
- 最后子步/资源退出失败恢复全部物理状态与历史；不得返回部分成功快照或使下一次调用受污染（T3/T4）。
- 设备阶段实际执行、单位/精度/次序保持，不能静默 CPU 补算或双重推进 dt（T4/T5）。
