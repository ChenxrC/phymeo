# Newton 1.7.0 刚体碰撞对照与 Phymeo 开发计划

**目标**　在同一输入上识别 Phymeo 已能复现的刚体几何、现有公共入口的缺口，以及 Newton 只能作离散对照的情形。先保存实际读回，再决定实现哪一项。

**交付**　13 个构型、程序化闭合网格、原生高度数组和可分引擎运行的检查器。现有 RR01–RR05 分别覆盖球、胶囊、凸体、有限旋转和凸体对凹网格。这里新增的网格案例将两个独立可动的形状都登记为凹网格。[案例库](../../../tests/reference_newton/rr/cases.json) · [两引擎入口](../../../tests/reference_newton/rr/baseline.py) · [已有 RR 验收范围](../../benchmarks/p65-collision-public-catalog.md)

## 运行与证据

每条路径在 1/128 s 内作规定平移。两个引擎用各自环境。Newton 1.7.0 的模型建在所选 Warp 设备，动态形状通过 `add_body` 登记为自由刚体，质量与形状所属刚体从最终模型读回。每个采样姿态只调用离散碰撞，间隙与表面膨胀均设为 0，禁用接触缩减。程序从实际形状 ID 确认配对，再读取最深接触的有符号距离、法向及支持点。对零接触的姿态，Newton 没有可读的正距离。动力学、摩擦力及接触持续时间另行验收。[Newton 1.7.0 碰撞管线、间隙与推测接触](https://newton-physics.github.io/newton/1.7.0/concepts/collisions.html) · [姿态与距离的官方读回示例](https://github.com/newton-physics/newton/blob/v1.7.0/newton/tests/test_heightfield.py)

Phymeo 使用 `phymeo.detect`。静态球对在 HOST 读回双方表面和间隙。两球扫掠在 HOST 和 TYX CUDA 使用相同路径，CUDA 项必须取得已完成的特征核、设备下载和同步计数，最终区间由 HOST 复核。落入 `gap` 的登记给出缺失的形状或配对。需要整段首次相触而 Newton 只给当前接触时登记为 `not_comparable`。这两类都单独计数。[Phymeo 球体扫掠](../../benchmarks/p65-collision-m2-round.md) · [Newton 推测接触的适用范围](https://newton-physics.github.io/newton/1.7.0/concepts/collisions.html#speculative-contacts-velocity-adapted-gaps)

| 案例 ID（前缀均为 `RR-`） | 难度及独立判据 | 要暴露的差异 |
| --- | --- | --- |
| `SPHERE-POSES`、`SPHERE-FIRST` | 易／中。相对中心距为 &#124;−3/4+3t/2&#124; m。起末净距均为 3/8 m，首次相触在 t=1/4。t=3/8 穿入 3/16 m。 | 同时检查原有能力、A→B 法向和采样契约。 |
| `U-NOTCH` | 难。小 U 的 x 投影始终落在大 U 的空槽内，整段至少余 3/8 m，而两个整体包围盒始终相交。 | 采用包围盒或凸包代替真实凹面会误报。 |
| `U-RIGHT`、`U-LEFT-HOLDOUT`、`U-FIRST` | 难。小 U 的封盖边分别切过局部 x=+1 和 −1 m 内壁。右侧越壁 1/8 m，左侧越壁 3/16 m。左例更换全部四边形的对角线、刚体登记顺序和两条路径。右侧连续行用 x=1/2+5t/8 单独预登记 4/5 首触。 | 同时检查壁侧、法向和有效穿入；不依赖接触点数量或排布。 |
| `RIDGE-POSES`、`RIDGE-MISS` | 难／中。3×3 网格给出 z=1−&#124;x&#124;。球半径 5/16 m，192 m/s 横穿。中点球心高出棱线 1/4 m 时穿入 1/16 m；抬至 3/8 m 时净空 1/16 m。两种轨迹都从分离到分离。 | 区分端点漏检、把棱线铺成平面和间隙误配。 |
| `SLOPE-FACE`、`RIDGE-FIRST` | 中／难。左坡的正交投影为 (−3/8, 1/8, 5/8) m。快速例先触棱线，横坐标 −3/16 m，t=3/8，后在 5/8 离开。 | 坡面法向与棱线法向不同。途中的一次离散命中只能证明该时刻发生穿入。 |
| `CYLINDER-RIM`、`CONE-TIP`、`ELLIPSOID-TILT` | 中。圆柱上沿最短距离是 3–4–5 三角形的 5/32 m。倒倾圆锥由尖端接地。倾斜椭球在竖直方向的支撑半径是 3/8 m。 | 分别排除胶囊替代平盖圆柱、上下对称的圆锥替身及轴对齐椭球。 |

屋脊球首触由独立圆截面求得。中心比棱线高 1/4 m，半径 5/16 m，所以相触时两者水平相距 3/16 m。此时两侧坡面无限延长后的垂足均越出各自三角形。沿 x=−3/4+3t/2 得出入区间 [3/8, 5/8]。Newton 在 t=0、1/2、1 三次独立求值。该区间只在连续行的解析预期中登记。两侧内壁的采样行也只验收公布的姿态。`U-FIRST` 为两个可动凹体的连续需求另存一行。[Newton 原生高度场与球的单元测试](https://github.com/newton-physics/newton/blob/v1.7.0/newton/tests/test_heightfield.py) · [网格的定向约定](https://newton-physics.github.io/newton/1.7.0/api/_generated/newton.Mesh.html)

## 两个凹网格正控的支持点读回

首轮实测中，CPU 按缓冲区首个最深接触点做对照，右壁和左壁的 A 支持点在 x 上分别偏离 0.0625 m 和 0.09375 m。CUDA 右壁的首个最深条目给出 +x，预期为 −x。并列条目的写出顺序可能变化，因此这条记录只描述当时取到的一个法向。[原判据和几何参数](../../../tests/reference_newton/rr/cases.json)

`RR-U-RIGHT` 与 `RR-U-LEFT-HOLDOUT` 现在保留缓冲区全部接触。每条都有原始行号、形状 ID、有符号间隙、按实际形状 ID 转为 A→B 的法向，以及 A/B 各自的世界支持点。与最小有符号间隙相差不超过原长度容差 0.001 m 的条目都标为 `is_deepest`。每个采样的 `deepest_set` 汇总总数、法向匹配数、A 内壁 x 匹配数和三项同时通过的数量。正控要求所有并列最深条目都满足原深度范围、分量容差 0.03 的法向及 A 内壁坐标。任一失败都保留该案例的两次姿态及所有支持点。

A、B 的局部 x 误差分别以 A 的实际内壁和 B 同侧的最外缘平面为参照，符号取“发布的坐标减去参照坐标”。B 的支持点可能位于其他真实面，因此另对每个支持点独立计算它到自己闭合 U 棱柱边界的最短欧氏距离。计算使用二维八边形和上下盖的高度，和两种三角化均无关。报告给出并列最深条目的四项误差范围，B 平面误差和双方曲面距离用于定位。Newton 在 BVH 边采样后分配两个求解器支持点，可结合原始间隙判断两个点是否整体偏移。[v1.7.0 网格边采样](https://github.com/newton-physics/newton/blob/v1.7.0/newton/_src/geometry/sdf_contact.py) · [接触点写入](https://github.com/newton-physics/newton/blob/v1.7.0/newton/_src/sim/collide.py)

## 复现与决策顺序

- [ ] 从集成工作树运行下列命令。每次使用新的 `--out` 路径，分别保留设备、版本、正负控、失败构型及原始读回。项目环境使用共享运行说明中的 `PYTHONPATH` 与 TYX 锁定版本。[安装与运行入口](../../../tests/reference_newton/README.md)
- [ ] 对比 Newton CPU、CUDA 的配对、法向方向、距离和内壁坐标。若任一参考端越界，保留失败并区分 API 配置、内核行为与手工推导。相同偏差只有查清原因后才可用于产品排序。
- [ ] 在 Phymeo 已实现的两球案例上检查 t=1/4、区间宽度、首触法向及末态分离。CUDA 必须有设备工作收据。已有能力退化时，先修公共入口。
- [ ] 用两引擎结果给下表排序。单个留出通过，只能解锁对应的形状与运动范围。产品实现与本对照目录分别提交。

```powershell
.\.venv-newton-1.7.0\Scripts\python.exe tests/reference_newton/run_matrix.py --engine newton --lane rr --device cpu --out rr-newton-cpu.json
.\.venv-newton-1.7.0\Scripts\python.exe tests/reference_newton/run_matrix.py --engine newton --lane rr --device cuda:0 --out rr-newton-cuda.json

python tests/reference_newton/run_matrix.py --engine phymeo --lane rr --device cpu --out rr-phymeo-cpu.json
python tests/reference_newton/run_matrix.py --engine phymeo --lane rr --device cuda:0 --out rr-phymeo-cuda.json
```

| 结果触发的开发任务 | 模块、依赖与成功条件 |
| --- | --- |
| 1 · 地形离散几何（中） | 若 Newton 的棱线、近失及坡面对照通过而 Phymeo 缺少原生表示，先在 `src/phymeo/constraints/collision_shapes.py` 定义静态规则高度数组、XY 尺度和样本方向。窄相在 `src/phymeo/geometry/collision_pipeline.py` 只枚举扫到的栅格，以真实三角形的面、边、顶点生成见证。最小放行范围为静态地形与平移球；三个离散案例都要通过，同时读回所属格、材料面和法向。 |
| 2 · 两个可动凹网格（难） | 依赖稳定的两侧三角面 ID 与各自姿态。复用 `src/phymeo/geometry/_collision_bvh.py` 和 `_closed_mesh.py` 的闭合曲面表示，做面 BVH 对遍历和三角面对实际求交。先做静止截面与规定平移，再分别处理实体包含及退化交线。放行时 U 空槽零接触、两内壁位置和法向均正确，能从两侧材料地址还原真实边界交点。两侧平移的扫掠首触须再通过 `U-FIRST` 的 6.25 ms 独立时刻。整物体 AABB 命中不计入窄相通过。 |
| 3 · 平移高度场扫掠（难） | 任务 1 的面、边、顶点归属可重用后，把扫掠包围盒与逐特征根隔离接入 `collision_pipeline.py`，并核对时间区间在切换特征时的先后。以 `RIDGE-FIRST` 的 3/8 进入、5/8 开离及抬高轨迹全段净空为验收。先证明 HOST，之后用 `src/phymeo/backends/_tyx_collision_kernels.py` 生成设备候选并核对区间。检查首触不能以子步采样代替。 |
| 4 · 曲面原语（中） | 依赖新增原语的尺寸、局部轴和刚体变换合同。先实现圆柱、圆锥与椭球在 `collision_shapes.py` 的显式参数，再增加需要的球–圆柱、平面–圆锥与平面–椭球窄相。三个案例分别核对锐边、非对称尖端和倾斜支撑，并用不同方向各补一个留出。任务 4 可在网格设计阻塞时先行。 |

**判停**　若同一设备上参考正控没有命中，保留形状类型、两侧姿态、间隙和实际返回值，再缩减为单对案例。若产品连续两轮只改善同一个姿态而不能通过相应负控和镜像，停止扩大构型，定位到宽相、面遍历、形状见证或时间隔离。两类非凸体含非零转动的连续检测、任意非流形资产和带摩擦多步解算，各需新的独立 oracle 和执行收据。本轮参考的展开范围为闭合连通 U 形体、5 种原生刚体原语与一张固定规则高度场。
