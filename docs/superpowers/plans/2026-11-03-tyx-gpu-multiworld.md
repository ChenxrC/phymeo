# TYX GPU 与多场景规模计划

**当前入口。** 阶段 0 的 G1 静态隔离与成本已完成。W=1、2、8、32、64 的两种布局在 Phymeo HOST、TYX CUDA、Newton CPU 和 CUDA 均保留了预期接触。W=64 时，现有 TYX 完整合批发布 32,640 行，其中 32,256 行是跨世界过滤。五个单查询暖态样本的中位数为合批 117.513 ms、逐世界顺序调用 31.698 ms。下一项为阶段 1 世界内配对。动力学吞吐、设备驻留和长窗口统计仍按后续步骤分别验收。[G1 原始口径及复现](../../benchmarks/p65-g1-world-isolation.md) · [三方向开发计划](2026-11-03-newton-reference-development.md) · [环境锁](../../../requirements/tyx.txt)

## 工作负载与独立判据

世界数量 W 和单世界复杂度 S 分别改变。每个场景都要有公共入口、解析值或既有单世界对照、一个反例和设备职责记录。复制世界时所有原点刻意重合，body/shape/material 使用相同的局部 ID。

| ID | 固定输入与扩展轴 | 放行条件 |
| --- | --- | --- |
| G1 隔离与规模 | 每世界 4 个半径 1/8 m 的球，x 为 0、3/16、2、4 m，所有 y、z 相同。W=1、2、8、32、64。留出把特定世界的第二球改到 5/16 m，并打乱世界 ID 与构造顺序。 | 基线每世界 1 个重叠对，间隙 −1/16 m、法向 +x（按局部 ID），留出只消除被改世界的接触。对重排按 ID、两侧见证及间隙比对。W=64 的现有完整接口有 32,640 个槽，世界内只有 384 对。计划中的分区宽相不得分配跨世界槽。 |
| G2 动力学而非独立查询 | 每世界以 z=2 m、v=0 放置自由球，g=−8 m/s²、h=1/128 s，推进 32 步，地面远离。另用已有 2 kg 滑轨与 ±4 N 四步驱动，交错正反控制，让相同模型产生不同状态。 | 半隐式自由球逐步核对 vᵢ=−8ih、zᵢ=2−4h²i(i+1)。滑轨 (+4,+4,−4,−4) N 时四步终点为 1/32 m、0 m/s。选一个世界复位或重放中间快照，其余世界的状态、力和历史与各自单跑一致。[滑轨输入](../../../tests/reference_newton/robot/cases.json) |
| G3 RR、RD、DD 混合 | 重用 RR 棱顶近失与接触，RD 球穿入三角形内部 1/16 m、节点均分离，DD 两条异体边在归一化 t=1/4 相触。先单世界，再 3 个共址世界，然后在可支持的几何查询中重复该组合。置换局部索引、世界顺序，其中一个世界留空。 | 读取两侧材料地址、首触时间或静态距离及来源。Newton 缺同语义的连续查询时用解析值及 Phymeo 单世界回归。几何输出不能代替动力学。再单列真实 2 N 布–连杆一子步，核对运动、反力及净动量。[RD 量与设备分工](../../../tests/reference_newton/rd/cases.json) · [DD 时刻与双侧权重](../../benchmarks/p65-collision-m2-triangle-pairs.md) |

| G5 失败与资源 | 在一个世界制造候选容量不足，令另一个有非零速度。交错两种拓扑、非连续 ID、空世界、只读环境几何和全局设备故障。 | 当世界边界可分时报告逐世界状态与容量需求，拒绝世界保留先前物理状态及历史，其他世界与单跑一致。设备整体失败时撤销同一提交边界内未确认的输出。重试可复现，无静默截断或 HOST 替代。 |

## 实施与验收顺序

1. **阶段 0（易）建立可重复的成本基线。** 拟建 `tests/scale/cases.py`、`tests/scale/test_world_isolation.py`、`scripts/benchmark_worlds.py`。先以 G1 两个同位世界核对现有独立调用、同一完整模型和 Newton 复制模型。控制间隙解析误差用 1 µm、单位法向分量 1×10⁻⁵ 作为简单球例的首版门槛。力学窗口复用其原预算。将冷启动与暖态分离。每个发现保留带单位的原始样本及失败输入。
2. **阶段 1（中）让碰撞工作量随世界内配对增长。** 拟新增 `src/phymeo/geometry/batched_collision.py` 和配套测试。输入为有序世界键、不可变模型和每世界 motion，内部将世界键映为紧凑槽并保存局部索引和前缀和。分区中只建 `Σ n_w(n_w−1)/2` 个允许的同世界槽作为第一步。后续稀疏候选可继续减少。公开结果按 world 和局部 ID 提供有界候选、拒绝、材料见证与状态。旧 `detect` 完整配对诊断保留。验收 G1/G5、交换输入顺序、分区 ID 重复与跨世界别名，W=64 的 384 槽是本试片上限。单一密集世界的复杂度另由 G4 检验。
3. **阶段 2（中至难）设备驻留及可观测性。** 拟新增 `src/phymeo/backends/tyx_world_batch.py`。先只支持球及固定基座给定关节布局。编译与静态上传一次，持有 device state 双缓冲、每世界容量/状态与紧凑输出。把控制输入、状态推进、聚合观测与完整快照设为四条可独立计数的边界。32 步暖态窗口内拓扑重上传与稳态额外分配须为零。关闭逐帧记录时要求不整表回传状态。确需 HOST 见证的 RD/DD 路径仍显式记读回。在 G2 全轨迹及 G5 复位/失败/重试通过前，轨迹不进入速度对照。
4. **阶段 3（难）异构调度与完整运动。** 拟新增 `src/phymeo/runtime/batched_scene.py` 和 `tests/scale/test_batched_step.py`。按签名分桶，将关节自由度、节点、材质、接触与历史绑定回 world。先同构，再混合成功/失败世界。批次未提交状态与上次可读状态分开。先通过 G2 的非同步控制、局部复位与回放，然后通过 G3 的受力子步。按 solver 公布可执行范围。若只是同一 Python 循环顺序调用 W 次，就保留作串行对照。
5. **阶段 4（难）按实测热点优化。** 对稳态记录判定主耗时在建表、调度/传输、HOST 几何复核还是设备计算。一次只动一个因子，再复测 G1 和 G4 的密集/稀疏留出。仅当主机提交开销主导，才在固定拓扑子步试图捕获与重放。仅当面级工作主导，才迁窄相。显存预估超过可用预算时标记容量上限，缩回已通过档。保留可复现的第一失败规模。

## 计量与停止规则

- 正确性矩阵先于计时。对同构批同时给独立 HOST 单跑、独立 TYX 单跑顺序循环、TYX 分区批处理。Newton 1.7 在独立进程、同一 GPU 上运行，只对匹配的形状、求解/检测阶段、时间与读回语义发布速度比。CPU 与 GPU 的不同验证工作量另列。多场景吞吐与单场景细分各有图表。第一轮目标机为当前 8 GB RTX 4060 Laptop GPU。
- 建模/JIT、静态上传、冷首步、暖态子步、必要读回、完整记录分别计时。每配置拟做 3 次独立进程配对，预热至少 5 个相同窗口，再测至少 20 个窗口，每窗 32 个子步。重型 G4 用原三帧序列单列。AB/BA 交替运行，不在同一 GPU 上并发对照。记录 warm p50、p95、原始墙钟及每次重复结果。主机墙钟在窗口两端同步。设备事件只包实际同 stream 的设备阶段。同步不可观测时写“未测”，多流或含主机工作的墙钟不可当纯 kernel 时间。
- 指标为**确认接受的世界子步数 / 端到端秒**、单世界延迟、每步 H2D/D2H/D2D 字节、真实与完成的 launches、同步次数、峰值显存及分配来源。输出三档为无逐帧记录、摘要、完整快照。拒绝步和等待、失败诊断分别记账，不混入成功吞吐。记录引擎/后端/精度、驱动、设备、输入版本、缓存和采样口径。显存区分本进程分配器峰值与整机观测，取不到的数据留空。
- 首轮拟定的优化门槛为 W=32 时端到端暖态吞吐比相同输出的 TYX 顺序单跑提高至少 25%，三次独立配对方向一致。W=1 延迟回退超过 10% 需解释或保留旧入口。它们是下一阶段的工程判断线，尚无测量值。W=128 及更高档须在新的分区 API、每世界上限及显存预检通过后再排入，不通过时记录瓶颈。原公共上限和物理预算保持。
- 世界串扰、遗漏接触、历史泄漏或容量截断，立即停止性能论证。若两轮只降低 kernel 时间或传输计数而相同窗口的端到端吞吐没有改善，停止继续加核，回到记录中的最大时间项。能得出“此配置暂不值得优化”也是该实验的有效输出。
