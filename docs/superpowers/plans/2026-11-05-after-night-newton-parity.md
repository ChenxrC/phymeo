# 本轮之后的 Newton 功能对齐批次

以 2026-11-05 夜间的已验公共接口为起点。执行入口是[本轮成果与留出](../../benchmarks/p65-newton-20261105-0800.md)，完整能力边界在[19 个功能族盘点](../../development/phymeo-newton-20261105-coverage.md)。后续保持多案例建立、差异模块补齐、整合验收的顺序。下面是下一轮待执行计划。

## 已有事实决定的顺序

- 公开构建器已经能处理多个可动刚体和可变形片；机器人资产、物体和有限桌面还走单独的交互会话。下一步首先补模型组合接口。
- 球、椭球、有限凸体与多球设备岛都有实际施力，但持续接触和材料规则散布在不同求解入口。下一步扩展受力与持久接触分派，并继续验证已有的完整检测目录。
- 目标软布的新选边方案清开了原腕杆阻挡，0.49–1.12 s 中供臂始终保持双侧载荷。受臂在最好的控制采样中仍在共同指面足印外 5.791 mm，原捕捉门还要求内缩 3.5 mm。继续工作应以可实现的末端位置、朝向与夹指足印为输入。
- 两世界三方接触链已在 HOST 和 CUDA 各完整推进 32 步。CUDA 的独立动量差 6.80×10⁻⁵ N·s 超过该额外试片原设的更严格门。这类误差作为应用精度与设备可用性的分开账目，不重新回到无限精度证明。
- TYX 已有设备几何分类、力律、积分和分世界射线。W32 球面专用路径有实测速度收益；复杂形状的通用窄相和场景编排仍有大量 HOST 工作。

这些判断来自本机具体接口与原始窗口。Newton 官方资料用于确认参照系统的分层和限制。Newton 1.7 将 Model、State、Control 和 Contacts 交给求解器；关节和材料支持随求解器而异。它的混合世界功能也有当前限制。[求解器矩阵](https://newton-physics.github.io/newton/1.7.0/solvers/index.html) · [世界语义](https://newton-physics.github.io/newton/1.7.0/concepts/worlds.html)

## 更大的独立能力族

柔性杆缆与扭转、MPM/塑性介质和流体、多步可微轨迹、批量 episode 与策略训练各自需要案例库、合适的求解器及独立验收。它们保留在长期功能差异表。先完成 A–F 的通用工程基础，再按实际应用需求选择其中一族。测试工具开源整理继续放在可运行框架之后。

## 每个节点的验收顺序

1. 锁定两个不同几何或拓扑的正例、一个失效例、一个留出变换。先说明单位、力学模型和真实可测输出。
2. 确认现有正常入口的缺失或错误，保留首次失败。实现最小可复用模块。
3. 验状态、力、力矩、动量、接触出生/退出及失败时的已发布状态。按应用尺度记录几何与数值误差，先固定可接受的物理精度范围。
4. 独立比较 Phymeo、共同材料律下的 Newton 积分、Newton 原生接触。三者的读数分别登记，原生力与净动量冲量不相等时保留两种数据。
5. 合入后做新组合回归和源码外 wheel 用法。作者工作树通过与用户可安装运行分别标记。

## 怎样判断成功或陷入循环

- **成功。** 出现新的公共能力，能换至少一种资产、形状或拓扑；有完整的实际运动与载荷记录；非法输入和拒步可解释；普通安装入口复现。单个案例通过属于其中一项证据。
- **还在推进。** 一次失败定位出新的机制差异，并留下可以直接检验的下一步。例子包括本夜把腕杆阻挡和有限指面未到位分开测量。
- **需要停止这条路线。** 连续两次遇到相同原因，且没有新增变量、机制证据或能力；反复调时间、位置、质量、容差只让原案例通过；只增加证明或报告，没有新增可运行模块；性能变好却改变物理工作或少读输出。
- **停止之后。** 保留最小反例及最后有效状态，决定更换模型能力、控制自由度或路线。把当前失败作为后续留出，继续能独立完成的模块。
