# 通用场景、接触生命周期与规模基线实施批次

> **For agentic workers:** Use superpowers:subagent-driven-development with the original authors in isolated worktrees. All project execution belongs to the parent serial queue.

**Goal:** 在已有真实动力学入口上补多物体机器人组合、跨步接触生命周期和固定规模成本数据。
**Architecture:** 复用已验 URDF 动力学、有限形状碰撞和接触材料律。场景层统一一次入步采样、提交和观测，接触记录不引入额外力；成本工具不改变物理模型。
**Tech Stack:** Python、NumPy、TYX，独立 Newton 1.7 对照。
**Spec:** [已授权后续计划](2026-11-05-after-night-newton-parity.md)的 A/B/C 首个可交付切片。
**Baseline:** c53e616b3226936bd945087cc0957b698e841160。

## 本批边界

A/B 是原高难节点的第一步，不把一批完成写成全部 A/B 已实现。继续使用当前材料定律及明确支持的几何。恢复系数、静摩擦记忆、任意机器人自碰撞、完整复杂形状 GPU 窄相不因这批自动完成。目标软布递交留在真正 3D 接收控制节点。

## Global Constraints

- 仅原三个作者隔离编码，父维护共享导出、现有 ContactScene 和集成事务。
- 项目 import、collection、pytest、数值、静态检查、格式化、构建、安装和性能运行全部串行，由父 fresh guard 后执行。
- 同源已绿集合不重跑。新功能必须有真实首次失败、独立物理检查和至少一种形状或拓扑留出。
- 不改变质量、容差、初态或输出字段来制造通过或加速。数值偏差与流程可运行性分别登记。
- 不改远程 CI、pin，不 push/main merge/发包，不新建周期任务。证据目录不清理。
- 真实力来自同一入步状态，发布状态和传感几何来自同一已接受状态。拒步时所有参与者、时间、事件序号均不前进。

## Review Focus

1. 两个自由物体必须互相施力，不能把两个独立单物体会话拼接成假联合求解。
2. 非指垫机器人结构和有限支撑保留，未支持的几何必须明确拒绝。
3. 接触重现、换面和世界局部 ID 复用不得继承失效载荷或混淆身份。
4. 只读 sample/geometry/传感调用不得消耗接触生命周期；失败后重试与直接成功必须一致。
5. 性能计时包含必要同步和相同公开输出，HOST 几何与设备执行分别报告。
