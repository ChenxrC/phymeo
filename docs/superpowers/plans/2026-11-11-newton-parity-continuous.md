## N1–N4：真实训练与规模

**N1｜中等｜代码已备，环境资格受容量阻塞。** [候选 profile 与实测空间下界](../../development/mujoco-tyx-cuda-profile-qualification.md)已记录；未安装 CUDA Torch，未运行新案例。沿[详细 GPU 计划](2026-11-11-mujoco-tyx-gpu-training.md)在独立环境验证两模型的实际 CUDA MLP→设备 action→连续物理→设备 observation，含默认/非默认 stream、所有权/CAS/生命周期负控。保留既有环境和 TYX pin；收齐版本/模块来源/输入绑定/复制与同步计数。不能用 CPU fallback 或静态检查代替此门。

**N2｜中高｜依赖 N1。** 独立 device VecEnv 和薄 RSL 适配；先冻结 final_obs、timeout、局部 reset、动作已提交后的失败语义。两任务各实际完成 4 次更新×16 步×8 world，核 GPU 参数确实更新和全部有效转移。此门只证明 PPO 链路，不能称“已经学会”。发生物理或后处理失败时报告真实已推进阶段，不伪回滚。

**N3｜高｜依赖 N2 的实际状态归属。** 在更新边界、空 rollout 时组合物理、policy、optimizer、normalizer、RNG、RNN 和 episode 状态。中途保存后继续，再恢复到同一实例继续，对比控制、物理和 learner 后继。缺字段、错模型、过期对象和晚失败均有负控；首版不承诺任意步/cross-platform bitwise 恢复。现在可以准备 manifest，不提前编造未定接口。

**N4｜高｜训练有效性与性能分开。** 三类任务：独立关节控制、持续接触支撑、受支持的分支关节机器人。运行前固定每任务的三个种子、训练预算、未训练基线和成功指标；评价可重复改善，不挑种子或临时改任务。随后测 W1/8/32/64/128/256 的端到端有效 transitions/s、更新耗时、显存峰值、传输字节、同步和 HOST 审计占比。256 是当前 task 接口上限，不是本训练流水线已合格规模；容量不足必须明确拒绝，不能丢 world。

只对模型、步长、精度和输出可对应的 Newton 子集比较。现有 action 提交局部加速不是总吞吐优势。HOST 转换/装配/诊断热点按测量排序；若提供降低诊断频率的生产模式，须单独声明契约与验证，不能静默删检查。

## ROB1–ROB2：场景与机器人

**ROB1｜高｜同 world 多参与者共同响应。** [冻结合同](2026-11-11-resident-multi-participant.md)采用 additive participant/layout/scene API。首版 resident 在同一入步状态装配跨参与者接触载荷，完整 J 投影，各机械块一次求解，全 world 一次发布；复用现有柔顺接触律，不宣称跨树隐式 KKT/QP。W1/W2/W4、每 world 1–8 participant，原几何/站点预算保持。固定双自由体、机械臂推自由盒、双臂工具三类，核双方力/力矩、分离/重入、完整 world reset/restore 和最后参与者晚失败。不能分别 step 后拼状态。MuJoCo-TYX 多自由根另设映射和原生对照资格，不继承 resident 结果。

**ROB2a｜高｜关节/执行器扩域。** 在已有 scalar joints、free root、PD、惯量/阻尼和限位上，先定义球关节 q/v、第一阶执行器状态、显式传动映射。球铰受矩、反向传动、阶跃/饱和/卸载及含执行器状态的恢复为基础库。闭环与 tendon 是后继独立节点，不一次塞进首片。

**ROB2b｜中高｜公共交互工作流。** 连接导入→目标/IK→有限执行器→碰撞→抓取/释放→回放；简单夹爪和 Panda 各一例，同时保留基础负控。禁止直接写位姿、焊接物体或时间/坐标特判制造抓取。依赖需要的 ROB1/ROB2a 和接触能力；已有单机器人基础可先复用。

## COL1–COL3：通用碰撞管线

**COL1｜中高｜统一凸支持族与能力表。** 复用现有[能力台账](../../development/collision-capability-matrix.md)和 backend×operation×owner×unordered-pair registry。球、胶囊、盒、凸包、圆柱、圆锥、椭球形成 28 类无序组合；后面三族已有有限 HOST support-map，不能称从零开发。先归并原设备 S/C/OBB/H 十类证据，补设备来源和通用 support 实现，不逐 pair 复制 solver。

新增组合固定分离/接触/浅交、反序、旋转和包含案例；距离/见证、完整 patch、真实载荷分别验收。矩阵每格记录后端、操作、所有者、范围、证据或明确不支持原因；几何通过不能自动授予 patch/双侧受力资格。圆滑支撑域与接触归并门在执行前冻结。

[COL1a 冻结合同](2026-11-11-device-convex-support-family.md)先补18类 device query，复用同一 support/GJK/EPA。父先接曲面来源准入、保守 AABB 和完整旋转 frame。负例的布置重叠量不是通用最小穿透深度，tests-first 必须逐族提供独立 depth/witness oracle。新曲面 patch 明确 UNSUPPORTED，真实受载拒绝，不能 HOST fallback；COL1b/c 后续另验。

**COL2｜高｜设备 mesh 窄相及变形来源。** 接已有 BVH，补有限三角面/边窄相、材料地址和有界 contact reduction。固定球/杆越有限边、凸体进入凹槽、薄壳正反面、固定拓扑变形面、双面交叉；检查漏检、重复刚度、完整力矩、错源及容量拒绝。先验变形几何，再接独立柔体响应消费者；不因几何通过称所有机器人树/柔体已联通。

**COL3｜高｜连续检测公共入口。** 复用已有时间搜索，统一平移、转动、固定拓扑变形路径。球穿薄板、旋转杆中途撞面、两面相向交叉覆盖端点分离/中途命中、近失、擦触及资源失败；输出首触括区与材料身份。逐面扫掠候选集合不是 CCD 通过。之后独立补跨特征身份、静摩擦/滚动历史，以承载→滑移→卸载→重入验收。

COL1–COL3 优先 resident。MuJoCo-TYX 原生 primitive/混合约束走独立模型映射与对照；不共享支持声明。预计算 SDF 和 hydroelastic 另列研究/实现后继，不能把 mesh 能力改名冒充。固定参照见 Newton 1.7 [碰撞文档](https://newton-physics.github.io/newton/1.7.0/concepts/collisions.html)。

## G1 与其余大模块

G1 保留独立兼容案例：先绑定部署资产/执行器与训练来源，再用已保存同输入对接触激活边界做有界通用诊断。现有 46.29 s 失败及约 -33 nm 的 native 额外接触均如实保留，未证明它导致长期漂移。不上调精度追求零 margin 位级一致，不调舞蹈初态/门来追绿；只有找到具体修复或得到新的可检验模型假设，才安排受影响验证与必要长窗。该支线不阻塞训练主线。

前三基础方向之外，仍按用户顺序保留：训练/可微中的多步梯度与辨识；批量传感/RGB/交互；跨域调度；布与体软体稳健折叠、抓捏、释放；杆缆、MPM/流体。它们需要各自案例库与接口研究，不由 PPO、G1 或凸体矩阵的通过代替。Newton 的能力也分[求解器](https://newton-physics.github.io/newton/1.7.0/solvers/index.html)和[多世界配置](https://newton-physics.github.io/newton/1.7.0/concepts/worlds.html)，不设“所有后端一次全支持”的虚假目标。

## 验收、停止与持续推进

- 每节点交付：公共可调用能力、预登记多案例/负控、实际来源与结果、资源边界和源码外安装调用。验收可以限定域，不能用文档或测试数量代替功能。
- 接受工程精度损失；容差、接触层/力律和能量门应由通用模型与案例预先决定，变更须说明后果。禁止输出后逐例调阈值，但也不为零穿透/位级等价无限推导而阻塞可用功能。
- 同一障碍连续两次有针对性的尝试仍未缩小原因，保存最小反例、标出受影响节点并拆分/暂停该支线；独立工作继续。计划研究阶段应以可开发接口与案例结束，不能无限追加理论笔记。
- 已绿同源和已完保存审计不重跑；只因新修改、接口集成或未解决风险增加适当验证。新批次需要时做一次集成 review/build/源码外验证，避免每份文档都全量构建。
- 仅新功能验收、实质失败/范围变化或用户决定时汇报。不按清单数/测试数计算整体百分比。整个 P6.5 和 Newton 功能对齐均未完成。
