# P1/P2 统一合同与运行框架设计

日期 2026-10-27；基线 `bf6c41a2305dd35c19f33052c2d1bcefd8cbec7a`；分支 `codex/p1-p2-runtime`。用户已授权按[大纲](../plans/2026-10-27-integrated-framework-outline.md)开启 P1/P2 长程任务，以下细化属于实施选择。

## 范围和完成条件

本轮交付可注册状态族、类型明确的场景/输入/设置/后端/报告、显式历史事务、物理端口和统一分阶段调度。旧布片/动态球是第一个完整消费者；另一个真实自由运动程序和端口交换验证无需更改调度器即可扩展。CPU FP64 与现有真实 tyx FP32 都须经过新框架执行。

不实施 P3/P4 机器人/四面体算法，不优化性能，不改旧接触模型与物理阈值。精度和结构性热点继续登记。无截止时间；全部验收、审阅、提交上传后停止并暂停续跑。

## 路线与边界

直接包装旧 `step()` 只能统一函数签名，不能控制子步、阶段、历史或全局验收。本轮选择将调度与计算分开：运行器掌握各子步的预测、位置迭代、速度准备/迭代、验证与提交；求解程序提供工作区阶段操作。保留旧入口和实验作为对照，不用其整帧 `step()` 代替新框架执行。

物理算法与内核留在 phymeo；tyx 只通过公共 API 执行设备计算。单次运行中的域采用同一 FP32 或 FP64 精度；跨设备/混合精度互操作尚不提供，应显式拒绝。模型和物理签名在运行器绑定期间不可变化，拓扑变更重新绑定。

## 有类型数据与注册

- `StateFamily` 描述名字、模型/状态/输入类型、完整状态和输入字段、dtype 字段、入口验证和候选不变量。字段为数值数组，构造标准类型时先复制数组，不调用用户对象虚拟 `copy()`。每个字段都检查形状、精度与有限性；新族可使用 q/v 等字段，不假设存在 position。
- `StateRegistry` 为局部显式注册表；拒绝重名/未知族，运行器绑定时固定所需合同。不使用全局可变插件表，不执行动态导入字符串。
- `DomainBinding(name, family, model)` 与 `SceneModel` 保存域身份和物理模型；`SceneState`/`SceneInputs` 用域名映射保留各族的原生类型，运行器入口规范化并拥有副本。容器本身不冒充深拷贝工具。
- `SceneState.history` 为程序声明的具名数值数组集合，`HistoryField` 指明 shape/dtype；字段、形状、精度、有限性必须与声明一致。所有跨 step 的乘子、warm-start、材料历史必须在这里，不允许藏在程序成员里。临时缓存只能包含可重建的派生数据。
- `StepSettings` 统一子步、位置/速度预算、归一化容差、参考长度/速度和是否记录子步。正整数、有限性、非负容差与正尺度严格检查，dt 单独传入并按状态精度量化。
- `BackendContext` 声明执行后端与 dtype，必须与程序能力匹配；运行资源由程序/工作区拥有并显式释放，不隐式回退。
- `StageMetrics` 为具名归一化残差与几何诊断，运行器检查有限且非负后判断阈值。运行器拥有接受标志和迭代计数，程序不能用自报成功绕过预算和验证。

物理签名包含模型和程序配置，绑定时固定；dt/迭代预算属于执行设置，不属于物理身份。计算指纹仅支持明确的数值/字符串/序列/映射/数据类结构，不使用 repr 伪造稳定身份。验证失败不通过改写配置继续执行。

## 求解程序与阶段合同

`SceneProgram` 声明 capabilities、物理签名和 history schema，并创建资源受控的 `SubstepWorkspace`。工作区消费规范化后的 scene/state/inputs/history、h 和 settings，操作仅限本次候选。

工作区责任：`predict()`、`position_sweep()`、`position_metrics()`、`prepare_velocity()`、`velocity_sweep()`、`velocity_metrics()`、`result()`、`diagnostics()`、`close()`。result 返回所有域候选及历史；diagnostics 保留独立载荷/几何证据。预测每子步只执行一次，sweep 不得再次推进时间。位置等效冲量已包含在速度重建中，不能再次施加。

`SceneStepper.step(state, inputs, dt)`：入口校验 → 全帧原始副本 → 对每个子步建立工作区 → 预测 → 有预算的位置迭代 → 速度准备 → 有预算的速度迭代 → 逐域候选/历史验证与可选独立物理验证 → 暂存候选。所有子步及资源关闭通过后，才返回可提交的最终状态与子步快照。

任何预期数值/执行失败返回原始全部域与历史的独立副本，不返回部分成功快照。后段失败必须恢复外层初态。程序/配置错误保留异常诊断，资源通过 finally 释放，调用者输入仍不变。资源关闭失败不可把已经算出的候选标记成功。重入/关闭后的使用明确拒绝。

运行器不按状态族/后端名称写 if 分支；注册合同和程序实现负责差异。程序为受信任扩展，不提供进程级恶意代码隔离；合同不支持任意隐藏副作用。学习 provider 只有配套同物理签名的独立 verifier 时才能运行，真实训练模型不在本轮。

## 物理端口

统一点端口提供世界坐标位置/速度、稳定索引/作用点、线冲量响应和候选状态增量。冲量单位 kg·m/s，刚体角冲量 kg·m²/s；力须先按明确时间区间积分。

本轮实现粒子点与刚体体坐标固定点端口：`response(impulses)` 返回所有端口速度变化，包含重复索引/共享刚体的交叉响应；不将每端口自响应误当全局独立块。`apply_impulses` 返回拥有所有权的新状态，不推进位置。通用双端口交换在同一世界作用点施加 p/-p，验证双方候选后一起返回；输入、历史不被修改。任意作用点应产生正确力矩。

机器人雅可比端口和软体插值端口是未来实现：将内部运动映射到相同点运动/冲量语义，不需要更改运行器。P2 的旧球接触仍使用已验证的标量投影算法，不能为了统一命名改变离散物理模型。

## 旧场景迁移与兼容

新增 NumPy 刚柔工作区，复用现有预测、距离/接触投影、残差、逐坐标速度重建和冲量记账算子，由新运行器组织迭代。着色参考只改变既有的距离顺序。新增 tyx 工作区，复用现有设备内核和资源约定，保留主机独立残差检查。

向现有实验暴露兼容的 CoupledState/Inputs/Result 适配器，使原场景审计器和回放生成器可直接验证新输出。模型固定点、姿态/角速度、力矩与每子步载荷都不能遗漏。单向受驱动反事实仍仅作为显式实验配置，不能通过放宽一般固定体不变量变成普通物理模式。

保留旧入口用于迁移对照，文档明确推荐的新入口。若代码共享需要重构，以不改变数值顺序和异常语义为约束，先验证回归再移动。不要双层 substep 或调用旧整帧 step 后宣称统一迭代。

## 验收

- 注册至少粒子、独立刚体两种真实状态族；未知类型/缺域/额外域/重复域/参数变更/错精度必须拒绝。用非 position 命名的小型自定义状态证明运行器不硬编码字段。
- 单对解析冲量、偏心力矩、重复端口的交叉响应、两方输入不变；实测端口速度变化符合独立解析结果。
- 一个真实自由运动程序和 NumPy/tyx 联合程序共用运行器；无需修改调度器即可替换同物理问题实现。
- 故障覆盖预测、位置/速度未收敛、候选/报告畸形、历史字段改变、第二/末子步失败、close 异常与设备异常；无部分提交、无泄露可复用脏历史。
- 学习候选自报通过但独立物理验证失败时拒绝；缺 verifier 明确拒绝。自动数学回退仅沿用已有单域 Stepper，本轮新运行器不暗中新增回退策略。
- 新框架短程 12 帧接触独立验收；完整 240 帧 FP64 与实际 CUDA 同源参考对照，记录全部状态/每子步审计与旧轨迹差异。数学未变时要求同后端同次序状态逐元素一致；差异必须解释并验收，不能放宽旧阈值。
- 原套件全回归、Python 3.11/3.12 核心、uv/pip、源码外 wheel 和远程 CI；实际 CUDA 不用 skip 冒充执行。
- P1 记录构造/校验测量，P2 记录真实完整 step 冷/热态、阶段/复制/验收成本和规模限制；未测项标为未测，不做速度优化。保留物理质量指标。

首次基线：当前环境 `pytest -q --tyx-mode cuda --require-tyx` 为 688 passed。后续证据必须对应实际提交，不能沿用这个数字宣布新增能力通过。
