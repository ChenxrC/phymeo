# P6.5 H1c：多域瞬时点载荷图

两臂与同一块布接触时，布和机器人共享关节的响应必须在同一图中合并。接续H1a，冻结不推进时间的多域响应算子；不修改既有P6单机器人程序，也不冒称完整碰撞/夹持程序已经接通。

## 结构与语义

`MultiDomainPointOperator(ports, left, right)`接收`domain -> PointPort`映射，以及等长的两端序列，每个端点为`(domain, point_index)`。每个域恰一个可信不可变快照端口；映射键必须与port.domain一致，状态存储FP64。调用者必须保证不同域表示不同物理状态，不能把同一状态重复包装并改名来绕过唯一所有者。

每条边接收一个世界冲量p（N·s），左端+p、右端-p。对于域d的有符号关联D_d，世界相对位置/速度为sum D_d*x_d/v_d，响应为sum D_d*R_d(D_d.T*p)。先累加该域全部接触，再调用一次底层响应/候选，保留跨接触、共享节点和共享祖先项。同域两端也经同一次聚合；同点自环贡献精确零。固定域可使用现有inverse_mass=0端口，其反作用载荷仍保留。

接口：`domains`有序tuple、`dtype`、`left`/`right`自有不可变端点tuple；`relative_positions()`、`relative_velocities()`、`response(impulses)`；`domain_impulses(impulses)`返回只读映射及每域点载荷数组；`snapshot()`、`validate_candidates(states)`、`apply_impulses(impulses)`返回只读域映射、各域状态均有独立所有权。apply先算所有载荷，再逐域求候选并验证，全部成功后才返回。任何底层失败不返回部分映射，且底层snapshot合同确保没有外部状态副作用；这不是SceneStepper跨子步事务的替代品。

空边合法；空ports仅在无边时合法。构造复制配置并按域名稳定排序；错域、错索引（含bool）、负数、越界、错误冲量shape/dtype/非有限明确拒绝。有限累加溢出为SolverFailure；底层SolverFailure原样传播。新增路由/聚合主机FP64，底层后端不变，不能声称图本身有GPU kernel。

## 物理边界

图是一种载荷路由算子，允许查询尚未闭合的几何对，不自行认定其为接触。它不选择法向/摩擦、不证明两作用点相同，也不约束相隔点间切向力产生的力偶。实际接触程序必须提供同一世界作用点或显式记录厚度力偶，验证间隙/接触侧后才调用；不能把此算子的相反线冲量误称为已验证角动量守恒。

不同域的所有量使用同一世界坐标系。固定基座/平台可吸收动量，只有无固定支持的粒子解析测试要求总动量守恒；机器人验证广义载荷及完整质量响应，不套用错误的开放系统守恒判据。

## 验收

- A/B/布三种质量、两条共享布边，独立矩阵`[[5,4],[4,6]]`（逆质量1/2/4）验证交叉响应、一次反作用、功率对偶和总线动量；共点例验证角动量。
- 同域重复边、自环、反向抵消、空图/空边、固定平台反作用与零速度；各域最多一次apply。
- 第二/最后域候选失败不得暴露部分结果，输入/快照/配置/返回所有权独立。
- 两机器人共享祖先及布重心端口的解析组合，使用完整R而非独立点质量。
- 实际tyx interpret/C++/CUDA多域组合：每个底层参与者调用期间都有completed_launches增长，解析值误差2e-5；明确主机图＋实际设备响应，不冒称完整物理step。
- 性能记录与本轮末统一审阅/打包/CI，未做优化或Warp差距声明。

H1c为后续唯一接触所有者提供响应与候选接口；完整场景仍需冻结非线性增量账本、接触/CCD响应、控制器及多关节审计。没有这些实现，不勾选H1整体或P6.5成功。
