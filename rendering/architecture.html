同一场景，两条渲染路线。

外观资产加载一次，动态帧按需提交。原生路线掌握 pass 与资源命令；可选高层后端消费共同契约。物理状态只读，图像与相机观测各自可追溯。

当前：契约与空实现零渲染 SDK · 零物理步进
虚线表示后续实现目标，非运行成绩。
物理边界

静止场景、封存轨迹或 Phymeo 已接受状态，只经 adapters/ 读入。渲染框架不求解接触、不修改状态、不重跑已有运动；显示接触力时，另绑定它所属的入步时相。

01资产复用，动态状态分离

Mesh、基础不透明材质、实例清单和方向光组成静态场景，交给 open_scene。SceneFrame 只提交节点位姿与来源；场景清单改变须更换 scene_key。

02控制能力按路线声明

原生路线目标是显式规划 pass、资源与命令。高层后端只承诺它能提供的模式和输出，不声称暴露同一套底层控制。

03输出继承来源与标定

outputs.py 定义 Channel；pipeline.py 的 CaptureRequest 选择通道。曝光相机与结果均绑定 frame_key。纹理、GPU 设备互通及真实图像生成仍待扩展。

七个模块，一条清楚的边界。

独立根目录 rendering/
独立包 src/phymeo_rendering
模块职责固定；后端实现按能力逐步落地。

assets.py
Mesh 与基础不透明 Material 声明；纹理是未来扩展。
scene.py
VisualScene 包含资产、静态实例清单和方向光；SceneFrame 只更新节点位姿，FrameKey 含 scene_key。
cameras.py
相机标定与曝光位姿，携带 frame_key；坐标、单位和裁剪面显式声明。
pipeline.py
CaptureRequest 选择相机、RenderPath 和通道；PassPlanner 声明原生 pass 计划，尚无具体执行。
backends/
open_scene → supports / capture / close 合同，尚无具体后端；原生 RHI 与高层参考适配是两条未来路线。
outputs.py
Channel、ImagePlane、Capture 声明；RGB、深度、ID 的通道身份与结果帧来源。
adapters/
静止场景、轨迹、Phymeo 读入；只读物理边界，不引入步进。
