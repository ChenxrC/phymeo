# Matched Panda frame 60: common-material external reference

This is a single-frame authoring tool, not a new renderer or quality gate. It has not been executed by its author. It reuses actual `panda_render_performance.bind_scene(...).scenes[0]`, source frame60 and the original detail camera at1280x720. Both native and reference explicitly have **no rubber normal map**; scanned base color/roughness, metallic payload, geometry, pose, directional lights, studio panels and original HDR remain unchanged. Exposure8 and PBR Neutral are fixed. No per-backend fit or scene simplification is permitted.

Three RGB outputs, each in its own process:

1. Selected explicit finite-near compact prepared package, one current exposure, no temporal history.
2. Original full-distance public NativeBackend, one-hop diffuse plus one-bounce specular,64 progressive batches x16=1024 primary samples per pixel, grid2 matching the near package.
3. Public SAPIEN3.0.3 PATH_TRACE,1024spp, max_bounces4, seed1 shifted-halton, no denoiser. The existing `capture_tiled` helper splits the **same1280x720 sensor** into16 disjoint320x180 rectangles. Camera pose, focal lengths and clipping are unchanged; principal-point offsets preserve every pinhole ray. Tiling has tile-local stochastic samples and is not claimed bitwise equivalent to a monolithic dispatch.

The SAPIEN path retains its actual public admission, including conservative all-vertices clip-slab limits. Unsupported material/clip/device/SDK inputs fail visibly. No SDK side door, fallback renderer, lower spp or changed light is tried. All original successes and failures remain on disk. A separate SAPIEN raster geometry-only capture provides optional ID/edge evidence; it is explicitly **not a PT AOV**. Raster studio is omitted only because RGB is not requested. Native geometry comparisons and reference-raster boundary disagreement are reported without erasing mismatches.

Each process seals actual scene, full frame/camera, studio/color settings, archive and helper hashes. Mesh paths differ between output directories, so the common identity compares exact decoded mesh positions/normals/indices/UV SHA alongside IDs; actual original paths remain in each inputs.json. Materials and lights are not normalized away. Any semantic input mismatch rejects the assembly.

Original RGB8 planes, raw PNG and RGB hashes are saved. Native actual raw-linear mean/current is saved separately. SAPIEN's real float32 HdrColor is copied **read-only before the existing display encoder**, assembled with the same disjoint tile layout, and saved without modifying display pixels. Full-frame views link to raw PNG; white-shell(150/151/154), fingers(156/158), rubber(2) use one identical native-ID bounding rectangle for all three original-pixel crops. No brightness-based ROI selection, crop resampling or simulated image.

These transport and BRDF models differ: finite-near transport is an approximation; native full is still one diffuse bounce and limited specular; SAPIEN has global multi-bounce transport and its own material/lighting implementation. The PT image is an external reference, **not ground truth**, and no equal-runtime or performance claim is made. Actual device names, source/DLL/shader evidence and elapsed wall time remain in receipts; same GPU must be checked from those diagnostics, not inferred from differing device aliases.

## Run by the serial execution owner

Use the already installed SAPIEN3.0.3 reference environment with NumPy and Pillow available. Do not install or change pins. `$examples` is the parent `rendering/examples`; `$runtimeSrc` is its public `rendering/src`; `$near` is the sealed final finite-near prepared package. `$fullDll/$fullShaders` must be a matching original full native source build, not the sparse DLL. Each output must be new.

```powershell
& $python -B -m unittest discover -s "$authorExamples/preview_matched_reference" -p test_contract.py -v
& $python -B "$authorExamples/preview_matched_reference/compare.py" run --examples $examples --runtime-src $runtimeSrc --prepared $near --library $fullDll --shaders $fullShaders --device-index 1 --sapien-device cuda:0 --output $newOutput
```

The launcher uses four isolated workers in near/full/reference-geometry/PT order. `summary.json` retains the exact commands/return codes and individual receipts. `index.html` is produced only when all three actual RGB images have matching inputs; failed optional raster geometry stays reported separately. Missing/failed PT leaves native outputs intact, with `partial_or_unsupported`, rather than substituting another image. Real cleanup requires native validation/live allocations zero and SAPIEN entity/temp-resource removal. Five focused HOST methods cover registration, actual-input mismatch, tile partition, limited interpretation and missing teardown evidence. No prior green suite is rerun.
Static interface audit before first execution: `load_episode` exclusively creates the fresh geometry directory; the caller must not pre-create it. Public native `read_linear_mean` returns owned1280x720 RGBA32F_LE,64batches/1024primary-spp and scene-linear-before-exposure. Compact `read_reconstructed_linear` deliberately omits batch/spp claims and labels reconstructed exposure; both extents, immutable byte lengths and actual formats are checked. SAPIEN tap receives actual float32 HxWx3 RGB plus exactly exposure/display_transform keyword arguments. Teardown checks use actual native device/telemetry and SAPIEN lifecycle fields, including its initialized false temporary-file flag for the geometry-only owner.

Existing dependencies only: Python>=3.11, SAPIEN3.0.3 + NumPy1.26.4, Pillow; local Vulkan DLL/SPVs and the validation layer for native validation. No MuJoCo/physics import is needed. The reused factory also verifies the normal-map PNG while constructing its unused scenes[1], so the checked-in factory asset set must remain present even though only scenes[0] is rendered. If the existing reference virtualenv lacks Pillow, append its already installed site directory via `--extra-site PATH` (repeatable). This flag is propagated into every child and appends after the virtualenv sites, preserving the virtualenv NumPy/SAPIEN precedence; an outer `python -c sys.path.append(...)` alone would not propagate to isolated children. There is no package installation or automatic dependency repair. Actual Python/NumPy/Pillow versions and imported runtime paths are recorded.
