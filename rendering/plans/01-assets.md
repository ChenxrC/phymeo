# M1 外观资产开发计划

> 状态：仅计划，2026-11-22。本文不表示校验、资产加载或渲染已经实现。执行者按 [通用指南](README.md) 逐项取得失败与通过证据。

**目标：** 使当前 `Mesh` 与基础不透明 `Material` 成为独立、可验证的资产声明，并形成首版不透明 glTF/GLB 的共享外观描述，为 R0 标定场景、R1 真实资产和 R2 材质比较提供稳定输入。

**结构：** 保持基础包只依赖 Python 3.11+ 标准库。资产对象描述外观，不持有物理材料、GPU 句柄或后端对象；静态清单、重复身份和实例引用由 M2 检查，真实文件解析与设备上传由对应适配器、后端负责。

**依据：** [框架说明](../README.md)、[当前 assets.py](../src/phymeo_rendering/assets.py)、[R0–R4 设计与指标](../../docs/rendering/README.md)。后续与 [集成计划](08-integration.md)、[统一验收](09-acceptance.md) 对照，不将无设备单测折算为实渲通过。

## 文件与测试归属

| 归属 | 路径 | 本模块责任 |
| --- | --- | --- |
| 产品独占 | `rendering/src/phymeo_rendering/assets.py` | `Mesh`、`Material`、首版 glTF/GLB 规范化外观描述、纹理色域与材质槽语义。 |
| 测试独占 | `rendering/tests/test_assets.py` | 标准库 `unittest`；含自有小型 GLB／纹理夹具，直接由测试以 json/struct/zlib 构造，不依赖 SDK 或原归档。 |
| 文档独占 | `rendering/plans/01-assets.md` | 记录计划与后续证据入口。 |
| 协作边界 | M2、M5、M7 所有文件 | M2 处理清单引用；M5 用原生或 SDK 解码并上传，遵守 M1 共同语义；M7 提供源文件、许可和来源绑定。需要变动时交给对应负责人。 |

不修改物理包、根项目依赖、控制器或轨迹。不得为了首图把碰撞几何无标识地替代为外观资产。

## 输入、输出与上下游

当前准确字段：

| 类型 | 输入 | 输出与消费者 |
| --- | --- | --- |
| `Mesh` | `id: str`、`uri: str`；网格局部坐标已是米 | 不变的网格引用，进入 `VisualScene.meshes`，由实例的 `mesh_id` 引用。 |
| `Material` | `id`、三分量线性 RGB `base_color`、`metallic`、`roughness` | 不透明金属度／粗糙度声明，进入 `VisualScene.materials`，由实例的 `material_id` 引用。 |

上游为程序创建场景和 M7 数据适配。下游为 M2 静态清单、M5 后端的 `open_scene(scene)`；动态帧不复制或重建资产。

当前没有纹理、UV、切线、透明模式、文件摘要和许可字段，也没有资源加载器。下列 R1/R2 工作是本模块的计划交付，不是现成接口：M1 定义共同外观描述与数值语义，M5 做实际解码／上传，M7 交付已绑定源文件和许可。新增公共字段必须先经 G1 冻结，并保持当前构造方式有效。

## 顺序开发步骤

### 1. 固定无设备资产校验

- [ ] 在 `test_assets.py` 先写 `test_opaque_material_preserves_linear_values`、`test_material_rejects_nonfinite_or_out_of_range`、`test_asset_identity_is_not_normalized`。执行者先确认缺少校验引发预期失败。
- [ ] 在现有冻结类型上实现局部构造检查，保持字段名、顺序和默认行为。`id`、`uri` 必须为非空白字符串；不隐式裁剪、改大小写或规范化 URI。
- [ ] `base_color` 必须是长度为 3 的不可变元组；三个分量、`metallic`、`roughness` 都是有限实数且在 `[0, 1]` 内。拒绝布尔冒充数字，不夹紧越界值、不自动执行 sRGB 解码。
- [ ] 以 `TypeError` 区分错误类型，以 `ValueError` 区分非法值；诊断至少包含字段名及资产身份。验证端点 0 与 1 均可声明，实际后端的额外限制由能力诊断处理。
- [ ] 运行该文件全部用例，保留具体命令与结果；不得仅将负例改为接受输入。

### 2. 验证声明不触发加载与状态修改

- [ ] 写 `test_mesh_uri_is_a_declaration_without_io`：使用合法但不存在的本地 URI，构造 `Mesh` 应成功且保持原字符串。文件不存在须在后续真正解析时显式报错。
- [ ] 写 `test_material_rejects_mutable_color` 和冻结字段写入负例；禁止把外部列表留在冻结对象内部形成可变别名。
- [ ] 保留一个网格可被多个实例引用的输入能力；不要在 M1 为每个实例生成不同网格身份。
- [ ] 检查基础导入只使用标准库；不得通过资产构造触发 SAPIEN、MuJoCo、Torch、网络下载或物理步进。

### 3. 提供集成所需的确定性材料输入

- [ ] 在该测试文件内定义小型、明确标注为测试的三种材料：金属 `(0.7, 0.7, 0.7), metallic=1, roughness=0.2`；塑料 `(0.2, 0.3, 0.4), 0, 0.5`；橡胶 `(0.03, 0.03, 0.03), 0, 0.9`。它们是数值测试夹具，不是实物标定值。
- [ ] 将字段约定与 M2/M5 交接；实际 R0 场景夹具由集成负责人建立，产品代码不得依赖测试目录。
- [ ] R1 接入外观资产时，由 M7 保存原始 URI、许可证、内容 SHA、米制转换与 visual 局部变换。缺资产和不支持的格式必须列出，不能靠无日志的代理几何蒙混通过。

### 4. R1：不透明 glTF/GLB 共享外观描述

- [ ] 先在 G1 协调新增数据合同，再编写实现：必须保留 `Mesh(id, uri)` 和现有四参数 `Material` 的合法构造，新增数据采用有默认值的可选字段或独立不可变描述，不复用现有 `uri` 字符串塞入未说明的槽号。共同描述由 M1 拥有，M2/M5/M7 接受同一版本。
- [ ] 描述至少覆盖：源资源键及内容 SHA、mesh/primitive 身份、三角索引、POSITION/NORMAL/TANGENT/TEXCOORD_0 的存在性和读取布局、局部节点变换、材质槽映射、纹理角色／图像身份／采样器。M1 的描述不能只说“有一个 glb”，让两个后端各自猜字段含义。
- [ ] 规范化目标为米制网格局部位置、明确的节点到 visual 变换与确定的 primitive 顺序。遵循源单位与节点变换，单位转换只应用一次；已有 glTF 米制数据不再次乘毫米换算。源节点变换和已烘焙变换分别记录，防止重复应用。
- [ ] 首批支持静态不透明三角 primitive 与显式 normal；使用纹理时要求 UV0，使用法线纹理时还要求显式 tangent（xyz 与 handedness）。不使用纹理的网格可以省略 UV。缺少必需属性、越界索引、稀疏／压缩 accessor、蒙皮、morph、透明模式或未登记扩展，必须明确返回不支持；不能静默忽略后渲染错误外观。
- [ ] 对缩放与基变换，交付统一变换规则：位置应用完整变换；法线用逆转置；切线正交化且 handedness 随反射变换调整。初始实现若仅支持刚体与正均匀缩放，须将非均匀缩放／反射列为明确不支持，不能只变位置不变法线。
- [ ] 将多个 primitive／材质槽展开为明确的实例或子网格引用。同一逻辑节点允许多个 visual 实例；每个当前 `Instance` 仍只有一个 `material_id`。不得把所有 primitive 都绑定为首个材质。
- [ ] 先写 `test_owned_glb_preserves_attributes_and_material_slots`、`test_owned_glb_applies_node_scale_once`、`test_owned_glb_rejects_missing_uv_or_bad_indices`。测试自行构造 GLB header、JSON/BIN chunks 和两个三角 primitive，期望坐标／槽号直接写成独立常量，不调用产品序列化器生成“参考”。
- [ ] 为 G1 冻结的描述实现无 SDK 的合法性与语义检查；M5 允许调用真实原生或 SDK 解码器，但必须把其解码结果对照该描述，不能另定米制、轴向或材质槽约定。

### 5. R2：共享纹理与金属／粗糙度语义

- [ ] 先在 G1 固定纹理绑定的角色、图像 URI／摘要、UV 集、wrap/filter 和色域。首版只接收 OPAQUE 的基础色、metallic-roughness 和 normal 绑定；其他角色须列入明确能力扩展，不能由后端私自猜测。
- [ ] 基础色纹理 RGB 按 sRGB 转成线性，再乘已有的线性 `base_color`；metallic-roughness、normal 属于线性数据纹理，不应用 sRGB 解码。金属度读取 B、粗糙度读取 G，并乘各自因子；normal 按切线空间及 tangent handedness 解释。规则依据 [Khronos glTF 2.0 官方规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#materials)。
- [ ] 两后端接收相同 UV 方向、UV 集、纹理角色和采样器。若 SDK 自行翻转纹理坐标，M5 适配必须显式抵消并报告实际处理；不把设备默认值当作共同合同。
- [ ] 先写 `test_owned_texture_distinguishes_srgb_and_data` 和 `test_owned_texture_preserves_corner_orientation`：在自有 GLB 中嵌入程序生成的 2×2 颜色图及数据图；用不同角点颜色检测上下翻转，用同一 0.5 样值检测色域错误。
- [ ] 数据纹理 0.5 应保持 0.5；基础色 0.5 的线性值按 sRGB 分段函数为约 0.21404114048223255。字节夹具则以实际 `128/255` 作为输入计算期望，不能把它冒称精确 0.5。
- [ ] 夹具使用明确的 UV 采样位置和 nearest 采样器，使角点识别无需宽松图像阈值。测试覆盖不同 primitive 的材质槽、roughness 与 metallic 通道互换、缺 normal tangent、纹理 SHA 不匹配等负例。
- [ ] R2 真实捕获时，M1 交付相同外观描述及纹理摘要，M5 记录实际解码、上传、线性照明与显示转换；采样、曝光、色调映射和降噪不归 M1 实现。

新增可计算验收（仍属计划）：

| 对象 | 正例与目标 | 负例与拒绝条件 |
| --- | --- | --- |
| 自有 GLB | 两个 primitive 的属性、索引和材质槽逐项相等；槽错配数 0；1 m 基准尺寸在正均匀缩放2后的结果为2 m，最大坐标误差≤`1e-6 m` | 索引越界、长度错配、缺必需UV／切线、未支持扩展均拒绝，不产生部分“有效”描述。 |
| 属性方向 | 法线单位长度误差≤`1e-6`；已声明变换下法线与手算方向的最大分量误差≤`1e-6`；切线符号与夹具一致 | 故意仅缩放位置而漏掉法线变换的结果不能通过描述一致性检查。 |
| 纹理语义 | FP64 sRGB参考值误差≤`1e-12`；线性数据不改值；两个材质槽和4个角点身份全部一致 | 把数据当sRGB、把基础色不解码、交换G/B、翻转UV，至少各一个独立反例必须被检出。 |
| 两后端交接 | 共同资产描述与源SHA相等；每个已支持primitive和纹理角色均有实际消费记录 | 后端能力不足可以明确失败，不能丢纹理后宣称与参考相同。实际高光／阴影比较仍按R2图像验收。 |

## 正负例与可计算验收

| 层次 | 用例 | 计划判据 |
| --- | --- | --- |
| 单元正例 | 上述三种材料与合法 URI | 字段逐值相等；局部校验不改变任何输入分量，最大绝对差为 0。 |
| 单元正例 | 同一 `Mesh` 被 M2 两个实例引用 | 静态网格清单条目数为 1，实例数为 2，引用解析失败数为 0；设备上传次数另由 M5 观测。 |
| 单元负例 | NaN、正负无穷、`metallic=-0.01`、`roughness=1.01`、错误颜色长度、布尔值或可变列表 | 每个独立用例均拒绝，字段诊断正确；不得返回被夹紧或转换的替代声明。 |
| 单元负例 | 空白身份、空白 URI | 拒绝数等于负例数；原输入不变。 |
| R0 集成 | 同帧同机位三材料标定桌 | 资产及材料声明在两种渲染路线间逐字段一致；两次采集前后物理步数增量为 0。真实图像由 M5 提供。 |
| R1 集成 | Panda 基座、腕、手指的外观资产 | 实际使用资产的来源／许可／SHA 清单覆盖率为 100%；缺失件数量与诊断数量相等。几何锚点误差由 M2/M7 和统一验收计量。 |

无设备单测不证明后端实际 glTF／纹理解码、显示转换、阴影或反射正确。R2 的材质画质比较必须另有真实图像与相同曝光输入。

## 执行与合并依赖

在独立包已由集成负责人安装的环境中，从仓库根目录计划执行：`python -m unittest discover -s rendering/tests -p test_assets.py -v`。

- M1 可先独立合并；保持现有 `Mesh`、`Material` 字段稳定。
- M2 依赖本模块的身份与数值范围，不重复做 URI 文件读取。
- R1/R2 的外观描述与纹理字段先通过 G1 协调，再由 M5/M7 接入文件格式和来源；M1 不导入 SDK。
- 对应 R0 的材料输入与 R1 的外观资产资格；为 R2 画质和 R4 资产复用提供前提，不独立宣称任何 R 节点完成。
- 基础校验可独立合并，但不能据此宣布 M1 的 R1/R2 工作完成。上述 GLB、属性、材质槽、纹理语义与两后端消费证据均属于后续完成条件；新增字段与来源加载规则经 G1 协调后更新集成与验收计划。
