# 从首图到八世界的最终验收

签收对象是一个可独立安装的 `phymeo-rendering` 提交、具名设备上的已验证后端组合，以及可以重新生成的机器人画面和相机观测。**R0 已在 RTX 4060 Laptop 通过，R1–R4 待测。** [原图、逐项结果与复现](../results/g3/README.md)。 现有架构图和画质意向图可用于沟通，验收表只填写实渲结果。

## 先冻结场景和测量口径

集成人在首次采集前提交以下夹具清单，记录资产、相机、光照、曝光、可见对象 ID、帧键、随机种子、测试配置及哈希。已发布场景作为只读输入。所有采集都检查输入快照及步数计数器，物理推进次数必须为 **0**。手工场景用带步进计数的测试数据源，Panda 和八世界使用封存状态及只读适配器。

| 样本 | 内容 | 独立参照 |
| --- | --- | --- |
| F0 标定桌 | 地面、铝／哑光塑料／橡胶、已知间距、非对称遮挡物、可移动主光 | 场景尺寸、屏幕投影及 ID 清单；预定受光区、高光区、投影区和主光移动前后方向 |
| F1 机器人回放 | 同一 Panda 和方块的两个真实姿态、一段连续 10 秒回放；固定、腕部两个机位 | 视觉资产清单及许可、源帧时间、由独立 FK 或原始发布位姿得到的基座／腕／指锚点；固定相机标定 |
| F2 相机标定 | 640×480，含 0.25–2 m 标定面、离轴标记、已知遮挡与背景；固定和转腕 | 独立针孔投影和射线–平面交点、可见实例标签，人工规定的轮廓剔除掩码；仅比较同一份几何 |
| F3 世界隔离 | 8 个带可区分状态或资产的世界，按 1、2、8 世界分批，各两台 320×240 相机；中途重置其中之一 | 每个世界／机位在相同种子、参数及时相的单独运行，含该世界自身 reset 的对照；每次曝光完整键 |

数值目标沿用[原路线](../../docs/rendering/README.md)。以下新增的像素编码、统计分母、测时及图像核查方法是本轮为可复验而约定的执行口径。变更口径应在新测量前记录原因、版本和受影响的对照组。

## R0–R4 的通过条件

### R0 · 能否真的看到同一张桌子

- **操作。** 在无窗口模式打开 F0，通过 `open_scene → supports → capture → close` 拍同一曝光，生成真实光栅 RGB、路径追踪 RGB、前向深度和整数 ID。改变主光方向再拍；另保留一次错误帧键和一次未支持组合的失败记录。
- **判定。** 两种成像路径都提供原始 RGB 和实际 API／设备信息。传感通道按能力表逐项记录由哪条路径生成。三个材质和遮挡物的预定内部点均命中对应正 ID，背景 ID=0；遮挡前后次序与清单一致。亮部和投影在预定区域按移动方向变化，附前后原图、剖面或亮度重心记录。空图、固定贴图、静默改后端、一次请求少回一个通道均判失败。
- **能力归属。** SAPIEN 的真实光追可交付参考图。自研光栅必须用独立的原生会话重复 F0；这个记录跟随 G3。声明“支持原生光追”另需原生 TRACE 的真实执行和图像证据。

### R1 · 机器人画面能否追溯到实际运动

- **操作。** 读 F1 两个姿态，展示真实外观并另存诊断线框。取基座、腕、指三类预先标记的锚点，按源位姿与 visual 局部偏移独立计算其投影；每帧记录资产、时间、相机和帧键。移走一件视觉资产、替换一个世界键各测一次。
- **判定。** 两姿态各三类锚点均有源记录和渲染对照，按 F2 同一像素约定比较可见标记，本计划取最大重投影误差 ≤1 px。场景中参与展示的视觉资产全部有单位、来源、许可和内容标识。缺件、错世界或错修订可定位，不能产生带正常标识的替代画面。

### R2 · 画质提升是否可见，以及快速档能否交互

- **操作。** 锁定 F1 同一帧和固定机位 10 秒轨迹的几何、材质、主光、曝光和显示变换。保存原生快速 PBR、参考光追未降噪高采样、低采样和对应降噪输出。预先写明每像素采样数阶梯、反弹数、种子组、参考的独立种子及 ROI。保留一组只改变粗糙度和一组只跳切／重置的图。
- **画质判定。** 在固定信号空间对相同 ROI 计算各档相对独立高采样图的均方误差，最后一档被比较的原始图平均误差须低于第一档，并附各档误差和样本数。以配对剖面检查增大粗糙度后的高光展宽，在回放标注接触阴影、金属反射和夹指运动；跳切／reset 后首帧与相同种子、空历史启动的对照检查旧像残留。签收人逐项记录通过或失败的可定位帧。图像参考与现实世界的差距须另有实拍标定才能量化。
- **交互判定。** 原生快速档单相机 1280×720、请求 RGB，预热后至少采集 300 帧，在记录的测试机上完成时间 p95 ≤33.3 ms。报告通道、采样、读回路径与所有慢帧。同帧参考光追另计离线成本。画质与交互延迟分别签收。

### R3 · 训练相机交出的 RGB、深度和标签能否信任

- **操作。** F2 的外部和腕部相机分别拍正视、离轴、翻转、遮挡、reset，申请 `RGB / FORWARD_DEPTH / INSTANCE_ID / VALID`。用独立参考对轴向深度和实例标签逐像素检查。
- **判定。** 每个机位、每种姿态分别报告可见标记的最大重投影误差 ≤1 px。距离轮廓 ≥2 px 的有效平面像素，最大前向深度绝对误差 ≤0.002 m；预期内部实例 ID 正确数／预期内部像素总数 = 100%。每个测试面和每类必测标记须有样本。边缘单列像素数及误差；背景深度为正无穷、ID=0、VALID=0，前景 VALID=1。检查翻转、端序、行长和同帧标识。采集与解码均在原生光栅路径有记录。

### R4 · 八个世界能否独立交付，以及成本有多高

- **操作。** 在相同设置下以原生光栅拍 F3，使用真实适配器及公共会话。逐世界、逐相机、逐时相与独跑对照；只在选定世界 reset。回放另导出一个带源时间的单世界高质量片段。
- **正确性。** 每个预定批次都有 `世界数 × 2` 个机位，各自的完整帧键、时间、分辨率、通道一致。对同一确定性光栅配置，ID 和有效掩码与独跑对照逐像素精确相等；同命中区域报告最大深度差，本计划取 ≤0.002 m，并报告每个视图的比较像素数。reset 后目标世界匹配重置对照，其他世界仍匹配连续对照。漏相机、陈旧键、不同世界互写均失败。
- **性能。** 对 1、2、8 世界分别先预热，记录预热帧数，再采集 **300 个完成的批次帧**。每批的所有机位均可由消费者取用后停止计时。报告批次耗时 p50/p95、总相机帧／墙钟秒、峰值显存、主机／设备复制字节和等待。编码单独计时，并列出相机实际采用串行、并行或批量提交。R4 首版要求三种规模都成功和测量完整，未设最低 FPS 或 GPU 零拷贝门槛。

## 执行顺序、复现与签字

1. 从独立渲染开发环境启动，登记源码提交、Python、图形 API／后端版本、设备、驱动和系统。按[合并计划](08-integration.md)先执行七个模块单测和 CPU 接口测试；随后登记唯一设备验证负责人，串行执行真实场景。每条验收命令保留实际选中数、退出码、跳过理由与缺失能力。
2. 约定以下命令从仓库根目录运行。下列测试文件及夹具由对应开发批次创建。前两条命令只需基础环境和测试工具；集成阶段须先准备具名图形后端、资产和设备。

   ```powershell
   python -m pip install -e ./rendering
   python -m pytest -q rendering/tests/test_assets.py rendering/tests/test_scene.py rendering/tests/test_cameras.py rendering/tests/test_pipeline.py rendering/tests/test_backends.py rendering/tests/test_outputs.py rendering/tests/test_adapters.py
   python -m pytest -q rendering/tests/integration
   ```

3. 构建发行候选时用独立打包环境运行 `python -m build --wheel rendering`。在源码树外的干净环境按生成的确定文件名安装 wheel，核对 `phymeo_rendering.__file__` 指向安装目录。安装实际声明的后端依赖，复制独立验收夹具和驱动脚本，在该环境执行 F0 原生光栅与参考光追。记录 wheel 哈希、导入位置、设备、输出及命令。基本包单独安装／导入也须成功。
4. 保存每项证据到同一轮验收目录，建议 `artifacts/rendering/<run-id>/R0` 至 `R4`。清单每行含 **关口／场景／输入哈希／代码与设备／后端、路径及通道／预期和实测（含分母）／状态／证据相对路径／签收人**。原始深度和整数标签用可无损解码的格式保存。缩略图和视频作为阅读入口。
5. 关口状态为待测、通过、失败或阻塞。没有设备、测试被跳过或关键资产不可分发时保留实际日志与替代环境验证范围。**最小闭环**需 R0–R3 加对应原生光栅证据；**独立引擎首版**还需 R4 与源码外安装复现。原生光追、设备直连训练张量及特定平台支持逐项附实测配置后才进入能力表。
