# 第一批 · Vulkan 4× MSAA 与传感真值

**目标**　在相同像素数下改善夹指和细杆的轮廓；默认 1× 保持当前行为。三位负责人在独立 worktree 同时编码，项目运行、构建、GPU 和视频编码使用同一个串行执行槽。总路线见[画质计划](2026-11-23-native-vulkan-quality.md)，输出合同见[传感通道](06-outputs.md)。

| 开发分支（共同起点 `1619a74c`） | 交接物 |

## 共同接口

`NativeBackend(..., resident=True, msaa_samples=4)` 通过现有会话拍摄。接受严格整数 1、4，默认 1；4× 缺原生接口、格式或设备样本数支持时明确拒绝。诊断记录请求／实际样本数、颜色 resolve 所用空间、传感采样方式、设备和资源关闭状态。输入相机、物理时相、分辨率、光源与材质修订贯穿两档。4× RGB 可以与任意既有合法的传感通道组合申请，深度、ID 和有效掩码始终取确定性像素中心。仅请求传感时沿用中心路径。

实现采用真正的 Vulkan 4 样本覆盖和深度测试。对经过当前显示变换的线性颜色作覆盖平均，然后执行一次 sRGB 编码；黑白交界 50% 覆盖约为 188 RGB8。留意当前 resident 片段和天空已写出编码后的 UNORM 值；编码空间的平均会把斜边压暗。实际图像格式、覆盖采样和设备限制记录到诊断。[Vulkan 光栅化与标准样本位置](https://docs.vulkan.org/spec/latest/chapters/primsrast.html) · [格式的样本数能力](https://docs.vulkan.org/refpages/latest/refpages/source/VkImageFormatProperties.html)

## B · 几何、运动与传感正确性，中高

- [ ] 独占新 `rendering/examples/msaa_calibration.py` 及 `rendering/tests/test_msaa_calibration.py`。构建斜边、亚像素细杆、前后遮挡三种不透明夹具，先以整黑、整白、已知半像素面积及故意错位的图测试独立参考。用像素方格与投影多边形裁剪求理想覆盖率；在显示线性域比较，边缘区由几何在渲染前确定。
- [ ] 保存 1× 与 4× 公共读回。在对比度固定的斜边上，边缘覆盖 MAE 降低至少 25%；对同一细杆的 16 个等距亚像素位移，比较相邻帧亮度变化与解析面积变化的绝对误差，平均下降至少 20%。归一化使用测试面与背景的实测稳定内部颜色。记录边缘像素数与全覆盖色，单列四分之一、二分之一、四分之三覆盖的 resolve 颜色。
- [ ] 对 RGB-only、RGB＋全传感、传感-only 三种请求校对：RGB-only 与混合请求中的 RGB 相同；两个采样档间的深度、ID 和掩码逐字相同，包含边缘、前后遮挡和背景。增加相机尺寸改变／reset，核对关闭后的资源，以及错误实现会被哪项挡下。交付原图、差图和数字报告。

## 集成顺序

父维护本计划与能力表。A 先交公共产品与新 DLL，B 独立检查算法／传感，C 在同一构建拍摄与计时。作者可并行写代码与夹具；需要执行时先取唯一槽并检查当前真实进程。按 A → B → C 交接设备，允许在 A 编码期间穿插独立 HOST 红绿测。父核验冻结输入、实际设备、RGB 与传感证据、负控、影片和性能后分别记录“已实现”“画质验收”“快速档验收”。旧版 wheel 的 G5 记录仍对应旧版；交付新版 wheel 时另作安装与渲染检查。
