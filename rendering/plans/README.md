# 渲染引擎开发计划与分工

目标是让调用方给出一个已发布场景帧和一次相机曝光，即可得到可查看的画面，以及与该画面对齐的深度和实例 ID。第一段可见交付是同一张标定桌的真实光栅图和光追图；第一版最终交付是同一接口支持 Panda 回放、腕部观测及八世界采集。

G1 在 `b018b32b` 接通资产声明、场景引用、位姿和相机曝光。G2 用同一张[双帧米制标定桌](../tests/fixtures/g1/README.md)接通程序场景、请求规划、输出帧包和拍摄会话。三个开发提交为 M7 `83db6d31`、M6/M4 `2666ac84`、M5 `932e16aa`。在 Python 3.11 和 3.13 上，渲染包的 142 项测试均通过。[拍摄集成测试](../tests/integration/test_backend_contract.py)使用两个人工像素校验通道、帧身份和关闭后的所有权。

下一批 G3 接入 SAPIEN 参考成像和原生 Vulkan 光栅。验收在同一张标定桌上比较真实 RGB、米制深度和实例 ID，并记录实际设备与路径。开发边界见[引擎架构图](../architecture.html)，首图的检查方法见[验收规程](09-acceptance.md)。

## 给模块负责人的七张任务单

路径均相对仓库根。每份任务单写明负责的产品文件、本模块测试、消费者及进入集成的条件。每个模块由一位负责人决定其公开接口。

| 模块 | 难度 | 可单独开发的第一件事 | 交给谁、交付什么 |
| --- | --- | --- | --- |
| [M1 外观资产](01-assets.md) | 中 | 用米制小网格和已知材质做资产解析测试 | 给 M2/M5/M7 可定位、有单位与来源的视觉网格和材质 |
| [M2 场景与帧](02-scene.md) | 中 | 用两个共享网格的实例验证节点、位姿和帧键 | 给 M3/M5/M7 静态身份、节点世界位姿和已发布时相 |
| [M3 标定相机](03-cameras.md) | 中 | 手算离轴标记的像素位置，用翻转相机做负控 | 给 M4/M5/M6 带同帧位姿、内参和裁剪面的曝光 |
| [M4 渲染路径](04-pipeline.md) | 中 | 枚举路径与通道组合，确定需要的有序阶段 | 给 M5 原生后端可执行的阶段顺序及不支持组合的诊断 |
| [M5 后端与图形设备](05-backends.md) | 高 | 在相同标定桌上分别启动参考后端与原生离屏设备 | 给集成人真正的像素、实际设备记录、能力表及资源生命周期 |
| [M6 图像输出](06-outputs.md) | 中 | 用手写小图解码深度、整数标签、掩码并检查字节所有权 | 给 M5 和观测消费者有明确布局、单位与来源的帧包 |
| [M7 外部数据适配](07-adapters.md) | 中高 | 从一个固定快照序列导出两帧，同步检查源数据 | 给 M2/M5 程序场景、Panda 真实状态和各世界只读帧 |

## 并行开发与串行合并

| 批次 | 分工 | 开始条件与可检查的结果 |
| --- | --- | --- |
| A · 固定接口和样本 | 集成人登记接口、测试环境和夹具；M1、M2、M3、M6 各写本模块实现与单测 | 所有人从同一基线创建独立工作树。用标准库数据就可验证引用、投影和字节布局。M7 可同时清查 Panda 资产授权，M5 可验证设备是否能创建。 |
| B · 组装第一次拍摄 | M4 完成请求到阶段映射；M7 完成程序桌面；M5 实现离屏光栅及参考路径。三个模块可用约定输入并行开发 | 合并前换成已合入的真实上下游。R0 必须通过公共接口产出两种真实图像，保留光栅和光追各自的实现及设备名称。 |
| C · 真实回放与测量 | M1/M7 接入两帧 Panda；R1 通过后，画质负责人和相机负责人并行准备 R2、R3 | 前者交同帧配对图、10 秒片段及耗时；后者交外部／腕部相机像素误差、深度误差和错帧负控。 |
| D · 多世界与发布 | 集成人串行执行 R4 和独立安装复现；M5/M7 分别处理设备资源与世界隔离问题 | 单世界结果用于逐世界对照，8 世界 × 2 相机全部能定位到原始帧；最终签收保存配置、原始输出、时延和显存。 |

模块负责人的“可合并”表示独立测试通过且接口可由真实消费者使用。整机签收按[上下游合并计划](08-integration.md)的 G1–G5 和[最终验收规程](09-acceptance.md)的 R0–R4 分别记录。R0 允许由具名的参考实现先证明双路径可行；自研首版另外要求原生光栅通过标定桌、快速展示、相机及多世界的对应检查。原生路径追踪有单独能力项，取得本机实测后再标记支持。

**若只有三位开发 agent 加一位集成人**，首轮可让 A 做 M1 资产与标定桌文件，B 做 M2 场景与帧，C 做 M3 相机及其解析样本。集成人建立共享测试入口。第二轮 A 接 M7 数据源，B 接 M5 设备和参考后端，C 先做 M6 输出再做 M4 请求规划。B 可先在独立分支开发，等 C 的请求和输出合同合入后接真实图形设备；无需同时占用多台 GPU。每次移交保留模块所属测试的负责人。

## 给开发 agent 的派工模板

> 领取 M__，阅读本页、对应任务单以及 08 中涉及你的接口。记录工作树基线，列出负责的源码与测试路径。用指定的正例和反例实现最小交付。提交时附上变更提交号、实现的能力组合、单测命令与结果、真实上下游接合结果或待接合项、已知限制，以及下一位负责人的复现入口。

若需要更改另一个模块的字段、单位或生命周期，先附一个会失败的生产者／消费者样例，交给该字段的负责人和集成人一起修订。集成人独占共享夹具、集成测试、打包配置及验收清单；每个工作树保留自己的单元测试。多人可同时写代码，同机项目验证按一个执行队列安排。
