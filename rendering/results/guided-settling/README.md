# 停稳后的间接光降噪

[查看两种模式的同帧原图](index.html)。选姿态 15，第 1 批左右相同。切到第 2 批，看暗红夹指的颗粒，再展开下方参考图检查指尖边缘。切到第 16 批，左右再次相同。每批新增 16 个光路样本，页面上的每次切换对应一次真实采集。

## 为什么停住后还会变粗糙

红板将光反射到夹爪背面。从某个像素发出的有限条随机光线，只有一部分会命中红板。相邻像素命中次数不同，暗面便出现颗粒。旧模式在运动首批借助邻域样本平滑显示，停住后第二批就关掉滤波。即使新增了 16 个样本，撤掉全部空间平均仍可能让第二批看起来更粗。

新模式保存当前姿态的直接光指引，对已累积的线性光照均值做空间滤波。同一实例上，深度与直接光接近的邻点才参与。随样本增加，逐批降低空间滤波权重，第 16 批起只显示原始均值。相机、物体或有效光照变化时重新采样并重建指引。首次和成熟批的逐字对照可在查看器中打开。

## 开启方式

```python
from phymeo_rendering.backends.native import NativeBackend

backend = NativeBackend(
    library_path=dll, shader_directory=shaders, device_index=gpu,
    resident=True, shadow_mode="ray_query", msaa_samples=1,
    indirect_mode="diffuse_bounce", progressive=True,
    spatial_filter="guided_settling",
)
```

若需要作相同输入的对照，可选 `spatial_filter="guided"`（仅首批滤波）或 `"none"`（直接显示累积）。三者均可独立读回原始浮点均值。新模式需要包含 settling 显示着色器和对应原生 ABI 的构建。


复现实拍使用原运动场景的公开存档。把下列路径变量替换为已构建的 DLL；选择本机支持这些着色器的 Vulkan 设备编号。输出目录须是新路径。

```powershell
python rendering/examples/guided_settling_study.py --library $dll --device-index $gpu --motion-source rendering/results/guided-motion --output artifacts/rendering/settling-replay
```

## 三个真实姿态的实测结果

以下误差均来自公开的 1280 × 960 原图。每个停点各用独立种子的 1024 样本图作参考。先对 RGB8 做逆 sRGB 转换，再按两指内部的 24,223 个有效像素汇总 RGB 均方根误差（RMS）。样本、相机和曝光在两种模式之间匹配。4c 使用 256 样本参考，其绝对误差单列在上一份报告中。

| 同姿态累计批数 | 每像素样本 | 仅首批滤波，RMS | 逐批减弱滤波，RMS |
| ---: | ---: | ---: | ---: |
| 1 | 16 | 0.004546 | 0.004546 |
| 2 | 32 | 0.009141 | 0.004337 |
| 4 | 64 | 0.006618 | 0.004039 |
| 8 | 128 | 0.004808 | 0.003773 |
| 16 | 256 | 0.003561 | 0.003561 |

旧模式第二批较自身首批上升 101.1%。新模式第二批较自身首批下降 4.6%，较旧模式同批下降 **52.6%**。预先设定的两道门槛分别是首批的 105% 和旧第二批的 80%，实测为 95.4% 和 47.4%。三个姿态合并后的误差在五个登记点逐次下降；逐姿态也都没有超过 10% 的相邻登记批次回升。首批到第二批，两指显示线性平均亮度的有符号变化在旧模式为 +0.000132，新模式为 +0.000101。[分姿态、区域、亮度和不确定性](scores.json)

轮廓区域共 30,379 个像素。第二批轮廓误差由 0.006261 降到 0.004196。姿态 15 新露出的有效前景有 48,191 个像素，第二批误差由 0.005527 降到 0.002742。其中属于右指的 69 个像素单独测得 0.013862 → 0.006438。四个后续登记批次的轮廓和显露区均满足各自预定上限。这个结果覆盖三个停点和这一次真实遮挡变化；单个像素仍会有采样波动。[同姿态独立参考](reference/pose-0015.png) · [右指显露区掩码](masks/pose-0015-reveal_right_158.png)

## 运行成本与历史正确性

| RTX 4060 Laptop，1280 × 960，全通道采集 | 旧模式 p95 | 新模式 p95 | 每模式样本数 |
| --- | ---: | ---: | ---: |
| 每个停点的首批，重画光照指引 | 76.4 ms | 83.5 ms | 3 |
| 稳定姿态第 2–15 批，复用指引 | 71.4 ms | 70.5 ms | 42 |
| 第 16–17 批，直接显示原始均值 | 70.6 ms | 63.3 ms | 6 |

计时涵盖 GPU 绘制、计算、同步和请求通道读回。各模式顺次运行，首批样本只有三个，这些耗时不足以证明两种模式有速度优势。新旧模式的单会话显式设备分配峰值均为 71,065,552 B，关闭空间滤波时为 65,822,672 B。每个停点只绘制一次指引，17 批中的前 15 批使用它。第 16 批起跳过额外显示计算。下一项优先将首批指引绘制、间接光采样、显示滤波和同步读回分别计时，再针对占时最大的阶段优化；当前配置尚高于 33.3 ms 交互预算。[耗时分组与独立原图核对](publication-check.json)

完整实验共 379 次公开采集、190 次额外原始均值读回、20 次额外指引读回。姿态按 0 → 15 → 24 顺序进入，姿态 15 另在全新会话采满 17 批逐帧对照。所有匹配批次的原始均值、深度、实例 ID 和有效掩码逐字相同；姿态 15 新开与从另一状态到达的输出逐字相同。本轮的运动范围是这三个停点，全部 25 个连续运动姿态的回放见之前的首批实验。[完整采集收据](summary.json) · [固定输入](protocol.json) · [原连续运动回放](../guided-motion/index.html)

首轮采集在新模式第二批遇到验证器误判。原生实现按 FP32 依次做除法、开方、减法；首版验证器按双精度算完后才转 FP32，两者相差一个浮点刻度。修正验证器并加入可区分两种算法的回归后，从新目录完成上述 379 次采集。权重公式与画质阈值保持原定义。原生后端另有 3 项主机与 5 项设备验证，覆盖相机、光源和物体移动、两次漫反射组合及发布失败恢复。图像显示的 30 个两指误差读数均由发布后的 PNG 与已绑定几何再次独立计算。[设备验证](native-build.json) · [本地浏览器验收](viewer-check.json)
