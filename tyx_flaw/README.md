# tyx 实现问题与性能交接

用户要求：在 phymeo 使用 tyx 的测试中，发现 tyx 实现相关的性能问题、可复现的 Warp 差距或应支持但未支持的能力时，记录到本目录，供负责 tyx 的 agent 持续迭代。

本目录记录依赖侧证据；phymeo 自身的同步策略、串行接触算法、每步重新分配等集成开销仍在 [性能瓶颈目录](../docs/performance-bottlenecks/README.md)跟踪。尚未定位到 tyx 的现象可以登记为“待归因”，不得直接写成 tyx 缺陷。

## 记录规则

- 每个问题使用 [模板](TEMPLATE.md)，文件名 `TYX-NNN-short-name.md`；优先提供最小独立 tyx 复现器及原始测量文件路径。
- 环境必须包括 phymeo/tyx 提交、Python、操作系统、硬件、执行模式、精度、数据规模及工具链。区分冷编译、缓存命中、预热与稳定运行；GPU 计时须说明同步边界。
- 性能结论同时记录物理/数值正确性、样本次数、失败数和分布。不要把测试总时长、解释执行、并发运行或第一次编译时间当作 CUDA 稳态速度。
- 与 Warp 比较须保持同一算法、迭代次序/预算、精度、规模、硬件及传输/分配/同步口径，记录双方版本与可运行脚本。未作等价比较就明确写“Warp 未测”。
- 能力缺口注明预期的依据：tyx 公共合同、后端硬件能力或上层算法需求；“硬件支持”不等于 tyx 已承诺支持。
- 写清已确认事实、待验证原因、tyx 与 phymeo 各自的代码位置及建议方向；尽量引用函数/文件，不粘贴大段实现。
- 当前 P1/P2 以整体正确运行为主，登记后不擅自更改 tyx 依赖或进行性能优化；影响正确性、资源安全或使验收无法执行的问题仍须解决/明确阻塞。

## 当前清单

目前尚无本轮已归因并完成最小复现的 tyx 实现缺陷。现有主机同步、串行共享体接触和缓冲区生命周期条目属于 phymeo 集成候选热点，不能据此断言 tyx 比 Warp 慢。T4/T5 将继续测试并在取得证据后添加独立条目。
